## Actual boundary and concrete failure

`src/app/state/app.ts:274–284,311` calls resetSocial on identity changes and expiration; same-session reconnect deliberately does not reset. The host PanelApi at 568–581 delegates fetchJson through game.ts:245 to client.fetchJson. `src/client.ts:362–365,374–379` already captures an identity generation and rejects stale HTTP results before core time/storage effects; it also supplies X-Allworld-Actor. Preserve this transport and its authority. The missing protection is inside the shared social client: its `call` catches `stale_identity_response` as an ordinary failure, and callers then mutate replacement state or toast and launch more work. It is inaccurate to claim the real host routinely returns old successful payloads; fake-host delayed-success tests additionally prove the social boundary independently.

Concrete reproducer: delay A's overview, reset to B and start B's pending overview; resolve A as the real transport's stale-identity error. socialClient.ts:267 clears B's syncing/loading, 274 sets B's error, and 276 may consume B's dirty request. A's delayed perform likewise reaches 253–255 and can toast into B and trigger B's sync. A→B→A defeats actor-string-only checks. A cleared send timer (346) can still be queued and call expire on every current outbox entry; a presence follow-up (469) starts reads for the replacement actor.

## Scope design — two independent generations

Use a non-reused actor-epoch token local to createSocialClient (a fresh opaque object avoids numeric wrap), captured with the host API reference and `host.view().session?.id ?? null`. Invalidate at the **start** of every resetSocial, before reactive writes, watchers, socket close callbacks or refresh. Preserve app.ts as the canonical transition notifier. A same-actor new PanelApi wrapper from start/attach is not itself an identity transition; ordinary screen start and same-session reconnect must stay idempotent. If attach observes a different actor, reset before exposing the replacement host. Recheck actor snapshot as well as epoch at completions; no fallback to overview.me as authority.

The shared actor epoch must **not** increment on thread/picker switch, same-actor city travel, normal reconnect, social-changed profile invalidation or screen unmount. Thread/picker request tokens belong to those local features. Same-actor global overview, people work and a legitimate send may finish while a different thread is shown. A cached thread can update by its captured id without changing the current selection. Preserve profileVersion separately: profile invalidation within the same actor still rejects older cards. Do not merge it into the actor epoch.

Capture before work begins; after every await, test the captured epoch **before** success/failure writes, finally-style cleanup, flag clearing, toast, sounds, callbacks, rekey/confirm, scheduling or follow-up requests. Each in-flight flag/timer has an owner token or equivalent epoch-safe ownership; an old completion may release its own resource, never a replacement resource. Do not clear replacement dirty flags on a stale return. Reset clears old dirty work; current actor coalescing still performs its one follow-up. Cancellation is optional resource cleanup, not the correctness fence.

`call<T>` remains never-throwing and retains SocialResult's existing shape. On an obsolete epoch or underlying `stale_identity_response`, return `{ok:false,code:'stale_identity_response',reason:'The active character changed.'}` without old payload/server wording; do not set transport=true or imply a send failed to commit. The shared client's callers silently abandon that obsolete completion. `perform` additionally captures its original scope, guards before good(result), toast and sync, and guards again after any supplied callback and awaited sync. External callers still receive a non-success; their own component state/toasts/drafts are outside this two-file proof and must keep their separate lifecycle guards. An already-sent request is not undone or automatically retried.
