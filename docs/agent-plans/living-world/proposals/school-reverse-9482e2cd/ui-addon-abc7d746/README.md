# Reverse selector UI add-on (source-only)

This add-on is based on Integration `eec14690544a4646e4cd8a5ad280d61bbe2709ca` plus the frozen pure reverse implementation patch `9482e2cdff947f726298040ee32c6102623277ee67ca1d05c84955999901f1d7`. Apply the pure patch sequence first (`reverse-road-edge-regression.patch`, then `reverse-gear-implementation.patch`), then `reverse-ui-controls.patch`. The add-on changes only `DrivingApp.vue` and the existing non-graphics `practiceIdentity.test.ts` fixture.

The panel adds native Drive and Reverse buttons with 48 px targets. They are disabled until the server reports the lesson running and the entry animation finishes. `null` requested gear preserves legacy three-field frames; only an explicit button selection adds `gear` to subsequently sampled frames. Changing direction discards unsent buffered frames so stale intent from the prior selection is not replayed. The transmission message derives canonical direction from the last server-confirmed `serverState` (missing v1 gear means Drive) and labels a different selection as requested while the current direction remains engaged during braking. Existing W/up throttle, S/down brake, steering, packet sequence, context fences, and neutralization paths remain in place. `clearHeld` clears both requested direction and input on load, resume, pause, context replacement, blur, hidden state, failure, completion, and unmount.

The existing inert SFC identity test is extended to observe explicit reverse/forward frames through the component's real input sampling and API path, check requested-versus-confirmed status during a shift, and confirm pause clears requested and held input. Existing coverage for an untouched three-field legacy frame remains intact. The test was not run. The renderer remains outside scope; reverse wheel rotation may still appear forward-only. No browser/native acceptance, migration approval, route permission, or deployment claim is made.
