# Active teaching save and recovery boundary

This batch adds a real Miniflare Worker/SQLite persistence fixture for the active teaching session. It creates a player through `/api/session` and the public onboarding/job/activity actions; it does not seed the lesson, career counter, cash, or progress. The fixture disposes and recreates the Worker over the same durable storage directory, reloads through `/api/life`, exercises a retry answer and a 1.25-second real elapsed-time check (well below the authored 40-second shift duration), then submits the three authored answers. It replays the exact final action intent concurrently and again after a second Worker restart to verify a single wage and durable receipt.

The source at production reference `a44629b38be751a9ad446051564704f6c3c6ae1b` cannot safely read an active teaching save. Its `src/game/systems/activities.ts` sanitizer reconstructs an activity from timing, choice, and paid fields only, dropping `teaching` and `teachingGeneration`. Its `src/game/systems/core.ts` then advances the ordinary timer and calls the normal activity completion hook; a teaching shift can therefore be paid without completing the lesson after that older build normalizes the save. Its `src/game/systems/career.ts` also reconstructs the career state without `teachingGeneration`.

Do not roll back to a build with that reader while a marked teaching shift may be stored. Use only a forward-compatible rollback target that preserves the marker/counter and blocks timer settlement. If an older build has already rewritten a save, the newer reader cannot infer from the stripped fields whether a marker-free shift is a legitimate legacy timed shift or a downgraded interactive shift. Recovery must not silently claim that the lost lesson state is recoverable or that an older deployment can safely resume it.

The feature's current forward safety boundary is the marker plus generation pair: the trusted server reader validates the lesson schema, job, venue, spot, and matching counter; marked shifts wait for input; each answer checks generation, stage, and revision; and the final authored answer completes through the existing activity completion path. Existing Node tests cover malformed/imported saves, generation fencing, action receipt races, and a failed final save. The new fixture is intended to add actual Worker durable-storage restart evidence for active and completed sessions.

The fixture now starts the first Worker with the trusted `INTERACTIVE_TEACHING_STARTS: '1'` binding, then disposes and recreates it without that binding while retaining the same SQLite persistence directory. It completes and replays the existing marker with the gate off, then creates a second player through public actions and verifies that the new gate-off shift is the markerless legacy activity with generation zero. The setting is a Worker environment binding in the test harness, never a request, save, or player-controlled value. These are intended assertions; they remain unverified until the fixture is run with the integrated Worker host wiring.

## Limits of this evidence

This Worker test is source-only until included in the central verification manifest and run on its supported Node/Miniflare toolchain. It does not run here and does not constitute production backup/restore evidence. It uses public APIs but does not inject corrupt persisted bytes; malformed marker rejection remains covered by pure/Node engine tests, not a Worker restart fixture. The existing Worker storage-layout/restart tests cover the store generally, not teaching markers. A separate Worker-level failed-write rollback test is not included in this batch. A follow-up could use a temporary SQLite trigger on the final wage-effect insert to make one real Worker transaction fail, then remove the trigger and retry the identical action intent; this is a test-only failure injection proposal, not evidence already obtained.
