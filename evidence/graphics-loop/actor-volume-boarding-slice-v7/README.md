# Actor-volume host adapter v7 — producer-provenance proposal

This is a separate, source-only proposal. It does not modify production renderer, vehicle, collision, or authority code. The adapter creates and privately owns its `Kit`, calls the shipped `loadBody()` and `buildAvatar()` functions directly, and returns opaque handles only. Callers cannot submit a material, shader name, source hash, cache lease, geometry, or actor root to the registration API. The body cache lease is observed through the actual `Kit.onDispose()` callback registered by `loadBody`; fallback materials are observed through the actual `Kit.eachMaterial()` factory path. The fallback stock callback is checked against the exact Three callback source digest in `source-pins.json`, so a monkeypatched `Material.prototype` cannot become the initial trusted callback. The actor/material/geometry ownership records live in private `WeakMap`s.

Before the first accepted sample, the test replaces a mounted production body's material with a new material that claims the production body program key but has a forged callback. The adapter rejects it because the exact material instance is absent from its private registration. A handle-shaped fake Kit and actor are also rejected at initial entry. The walker traverses the complete live actor subtree itself, rejects non-mesh renderables and unknown descendants, records each node's local/world transform and all geometry attributes, index bytes, groups, draw range, morph channels/influences, mesh transform, skin/bind matrices, bones, shader callbacks, texture/cache leases, and normalized appearance/presentation fingerprint. It compares this state again synchronously immediately before returning the sample. Registration and sampling both use a bounded iterative walk rather than `Object3D.traverse()` or recursive world-update helpers. The ancestor chain and actor tree are capped before geometry/material processing; each operation enforces 512 nodes, depth 64, 128 meshes, 100,000 triangles, 12 MiB of raw geometry attributes/indices, and 50 ms. Manual world-matrix mode, non-finite transforms/float attributes, unsupported renderable descendants, excessive groups/attributes/morphs, or a timeout fail closed.

A `HostFrame` handle is minted monotonically. Capture and validation must happen in the same synchronous turn; the snapshot token expires in the next microtask. Even a current sample returns `canBoard: false` and `routeAuthorized: false`. An unobserved pose, easing transition, disposed actor/Kit, changed descendant, unsupported renderable, forged callback, or changed ownership returns `unknown`/`refused`.

The test loader changes only how GLB URL imports resolve under Node and strips image/texture references before parsing the shipped bodies, substituting a 1×1 `DataTexture`. The mesh, rig, weights, clips, wardrobe generation, callbacks, and actual production `loadBody()` path remain in use. This is a provenance/lifecycle CPU test, not a visual result. It does not validate GPU shader output, cabin clearance, or the continuous door/seat/exit interval.

## Provenance and checks

`source-pins.json` lists exact production files and GLB bytes. The test rehashes every listed input before exercising the adapter; any mismatch fails immediately. `runtime-closure.json` lists the full local runtime/type closure, data assets, external dependencies, and exact test command.

The v6 README begins with an old “no test ran” sentence but later records the focused 8/8 test pass. That opening line is stale; v7 does not treat the inconsistency as new evidence. v6 remains a proposal whose focused contract test passed, and whose caller-provided provenance weakness motivates this adapter.

This folder has not been built, typechecked, or executed. The focused actual-source test is prepared for a supervised 96MiB Node run. A passing CPU test will establish only producer provenance and synchronous snapshot refusal behavior. A real consumer integration still needs to bind its host update turn, collect the actual parent chain, and prove pose evaluation before calling the adapter. Continuous entry, seat, exit and trajectory coverage remains unavailable; no interval provider is registered and all authority fields stay false.
