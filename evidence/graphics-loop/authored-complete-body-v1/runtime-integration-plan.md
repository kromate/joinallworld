# Runtime integration plan: complete authored body

This is a read-only integration plan based on the production body, creator, home, venue, and canonical-crowd APIs as they stand on 2026-10-09. The isolated authored-body prototype is not ready to replace those paths: it has only `idle`, `walk`, and `dance`, and its clothes and hair are still provisional.

## Existing runtime seam

The narrowest reusable seam is `loadBody()` in `src/scene/body/skinned.ts`. Its `SkinnedBody` interface is already the contract consumed by the creator preview, the home avatar, and canonical venue/home people. A loaded actor owns an object group, identity key, `wear`, `fit`, `place`, pose/action sampling, seat/work placement, foot contacts, and disposal. `createCanonicalCrowd()` is generic over that contract, so it does not need a renderer rewrite to host a second body implementation.

Today `loadBody()` has important behavior beyond loading a mesh: it resolves a shared GLB/clip cache, applies appearance morphs and uniform tint, creates the wardrobe and facial-detail renderers, samples still frames without a private animation loop, crossfades bounded transitions, solves feet, and handles body-family changes by asking the caller to reload. The authored adapter must preserve those behaviors at the contract boundary or explicitly report which are unavailable; a small adapter can keep scene callers unchanged, but it cannot make unsupported authored clips appear.

The authored prototype already has the right ownership shape for that adapter: a shared immutable template and clip cache, a per-actor cloned scene/skeleton/materials, and explicit actor disposal. It shares posed bones across the four `Body`, `Eyes`, `Teeth`, and `Tongue` skinned meshes. Its source hierarchy is 52 Mixamo joints, while the current production rig is 23 named Allworld joints. `rig.ts` maps those common joints and retargets the existing `idle`, `walk`, and `dance` clips. This is enough to establish those three motions, not the full scene contract.

## Minimum drop-in implementation

Add a separate authored loader/adapter behind the existing lazy body gate, rather than changing callers first. The adapter should implement `SkinnedBody` and own `loadCompleteCharacter()` plus `applyCharacterPresentation()` as one actor lifecycle. Its `object` is the complete authored root; `wear()` applies the normalized look and presentation in place when the body family is unchanged, and returns `false` when it must rebuild for a different family. `fit()`, `place()`, `sitOn()`, and `workOn()` must use measured authored bounds and preserve the caller's parent-space placement. It must not dispose shared template geometry or a skeleton used by other actor meshes.

Keep `loadBody()` as the fallback and make the loader choice explicit in the existing loader boundary. The creator preview is the first useful host because it already serializes normalized look changes through `wear()`/reload and keeps the legacy avatar visible on load failure. Once that path proves body-family, expression, hair, outfit, lighting, and disposal parity, the same adapter can be selected for the home player. Canonical home/venue people can then use the existing `createCanonicalCrowd<SkinnedBody>` queue without changing how actors are placed or replaced. Near-player NPC selection belongs in the loader policy, with existing authored/procedural stand-ins retained for distant actors, unsupported hardware, and failures.

The adapter needs a real action bridge before it can be used for all gameplay. `BodyPose` includes idle, walk, jog, sit, interact, dance, lie, soak, wash, bucket, cook, cook-low, eat, drink, and home-door, while `poses.ts` also requires transition clips for entering/exiting furniture and work, doors, and stairs. The authored prototype only retargets idle/walk/dance from `clip-pack.glb`. Those are the only proven mappings. Missing clips must use a deliberate compatible fallback or keep the legacy actor for that interaction; silently mapping every pose to idle would break sitting, work, and contact alignment. The existing pack contains the source clips, but the authored rig still needs verified retargets for jog, sit/use poses, transitions, stairs, and any pose used by the home/venue controllers. Verify root motion, feet, hand placement, and seat height on those clips before advertising support.

For action smoothing, `CompleteCharacter.sample()` currently stops the prior action when the pose name changes and starts the next at its requested time. The production body instead blends transitions from the captured current bone frame over a bounded interval and keeps the host responsible for stepping. Add a bounded crossfade in the adapter (or a reusable rig-level mixer transition) and expose `step(dt)`/`settle()` semantics matching `SkinnedBody`. Continue sampling ordinary idle/walk frames only when the host already updates; do not create an actor-owned requestAnimationFrame loop.

Identity should continue to be stored as the existing normalized `Look` plus seed, not as asset-specific morph indices. The current authored rig already maps body family, oval/round/long face, height, and broad/slim build to named morphs, and applies the existing expression choice. Keep those mappings in one translator. Its `unsupportedAppearance` must remain visible to callers until age, outfit, accessories, and regional cloth are truly implemented. The current presentation supplies a generic shirt/trousers and short-curls/bun styling; it does not yet reproduce the full wardrobe catalogue, Ankara/fabric patterns, Agbada/gown/gele/headwear/accessories, or regional fit. Do not claim creator parity while the UI can save choices the authored renderer ignores.

## Talking, blinking, and identity continuity

The authored asset has actual eyes, teeth, tongue, and retained facial morphs, so it is a better basis for expressions than the legacy atlas sockets. The prototype supports neutral, smile, grin, talk, and blink by writing body morph influences. The first integration should keep expression state separate from locomotion state: changing from walk to idle must not reset the currently selected smile, and changing a saved look must restore its base morph values before applying the chosen expression. `talk` currently oscillates jaw-drop from a time parameter; callers need a deterministic speech envelope or bounded talk pulse driven by the existing chatter/voice event timing, not a free-running actor loop. Blink should be a short timed close/open envelope and then restore the saved expression. The current legacy `SkinnedBody` has no public `setExpression` operation, so add it to an internal common actor interface or route it through the authored adapter's presentation state; avoid coupling dialogue UI directly to morph names.

## Concrete next step and acceptance gates

The next implementation should be one adapter in the lazy body module boundary, initially selected only by the creator preview behind an explicit development/feature flag. Build its `SkinnedBody` contract mapping for the proven idle/walk/dance actions, normalized identity fields, expression persistence, presentation disposal, scale/place, and failure fallback. Add contract tests against the actual authored GLB proving two actors have separate skeleton/material/morph state, the same normalized look survives reload, and disposal leaves shared templates intact. Then render creator cases for both body families, saved look edits, smile/grin/talk/blink, walk-to-idle transitions, and the unsupported outfit list. Do not put this adapter into home or NPC routing until the remaining pose/action table and full wardrobe coverage are either implemented or explicitly routed to legacy actors.

The asset has no embedded animations; it depends on the existing `clip-pack.glb` (pinned in `rig-report.md`) and the current retarget map. The required next asset work is therefore clip mapping/validation, not another body download: verify the available clip names against every `BodyPose` and transition in `poses.ts`, then add only missing authored-compatible clips if the existing source motions do not retarget cleanly. The current experiment checks three motions only, so no sitting, work, stairs, door transitions, feet/floor contact, or long-duration pose blend has been established.

The authored body is materially larger than the shipped body: 27,676 triangles across four skinned meshes versus the legacy 9,002-triangle body, before the prototype's added shirt/trouser/hair geometry and four extra draws. Measure the complete creator and near-player actor cost (download, decode, morph storage, draw calls, GPU frame time, and memory) on a supported phone before expanding NPC use. Keep the current low-tier/Data Saver/no-WebGL2 procedural fallback and lazy loading intact.
