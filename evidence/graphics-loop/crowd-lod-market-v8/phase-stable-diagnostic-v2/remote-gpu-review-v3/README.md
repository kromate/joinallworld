# Phase-stable v8 support/contact and request-lifecycle review, v3

This isolated remote diagnostic reuses the already-verified v2 CPU package and captures full-canvas source/compact frames after one real 2.4-second production-stride cycle for two saved Market identities. It preserves the source-first post-pause capture and requires the exact same sampled bone checkpoint across A/B.

The previous v2 run stopped before its first PNG because `actor-published` is exposed through `window.__marketLodLiveWalk.loadTrace()` rather than the render-status JSON. V3 reads that actual getter for every capture. A small tested contract requires the latest generation to belong to the selected actor and include the complete current body/recipe resolution and publication sequence; stale, failed, incomplete, or wrong-actor traces remain fatal. Captures persist that trace and its generation alongside numeric metrics.

The fixture uses `body.place(0, 0, 0, 0)` and production `SkinnedBody.solveFeet(heightAt => 0)` against a visible y=0 reference plane. Its status records raw sampled sole points before the last solve, post-solve sole points, support-solver outcome, and world-space min/max over deformed body and wardrobe vertices. The script gates numerical support residuals and camera-frustum AABB bounds, then stores the entire canvas; it does not infer pixel visibility from bounds or certify a venue floor.

CDP network evidence stores request initiator, frame/loader, response headers/status, completion byte count, failure details and timestamps. Browser network failures remain strict failures. The per-actor fixture load trace adds an epoch timestamp and generation stages so root can correlate body-load and identity/hash requests without waiving an abort.

The run remains a constrained headless Chrome/ANGLE SwiftShader diagnostic. It cannot establish hardware rendering, mobile performance, all-look quality, whole-market budgets, or production acceptance. Root must review all 10 actual frames and the contact/request telemetry.
