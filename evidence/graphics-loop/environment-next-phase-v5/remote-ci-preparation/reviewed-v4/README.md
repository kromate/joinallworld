# Reviewed v4 full-slice diagnostic package

This is a new remote-only recipe on `codex/graphics-environment-next-phase-v5-review-v4`. It preserves the failed v2, v3, and v3-fix1 receipts and source trees. V2 exceeded its process-group ceiling during the full application compile. V3 failed because the addon phase referenced an unimported `assertPinned`. V3-fix1 corrected that helper import and passed the source seal, full pre-verification, vendor compile, and addon compile; its full-app phase exceeded the old 220 MiB group ceiling by 0.211 MiB (peak 230,907,904 bytes) after 3.434 seconds.

V4 retains the exact content and source verification boundaries while raising only the remote diagnostic runner's owned process-group ceiling to 384 MiB. This is diagnostic headroom to measure the complete compile, not a game, production, mobile, or release budget. The Node old-space cap remains 96 MiB, the end-to-end runner remains limited to 25 seconds, and compilation stays serial with `GOMAXPROCS=1`. The runner records each phase's wall time, peak sampled process-group RSS, peak RSS by PID/command, and overall phase/PID peaks. It samples Linux `/proc` every 25 ms, so the monitor does not spawn `ps` into the measured group; very short-lived processes may be absent from the sampled list. A final strict `/proc` scan must find the wrapper and no other group member before the receipt may report `cleanupVerified: true` or succeed.

The source seal still covers the full `src/`, `public/`, Three r180 addon tree, lock/package files, and exact private fixture/recipe inputs. A separate process verifies the full inventory both before and after compilation. Vendor, addon, and application compilation use fresh Node processes. App/addon loaders hash every consumed input buffer against the sealed pin map and recheck consumed sources after compilation. The output seal verifies every emitted file and consumed input, checks the import closure across app/vendor/addons, and requires all forty city map chunks. Three core and module are emitted as siblings, preserving the installed module's relative import.

The one-copy finalizer hashes the copied public files and stages explicit static routes for review. All generated files use `*-v4` paths so earlier attempts remain intact. The workflow is prepared for parent review and is not installed into `.github/workflows` by this folder.

No compilation, test, server, browser, or remote workflow has been run for v4 preparation. A successful diagnostic package would establish only that a complete review fixture can be assembled within this remote harness; it would not establish visual quality, frame time, production size acceptance, or phone performance.
