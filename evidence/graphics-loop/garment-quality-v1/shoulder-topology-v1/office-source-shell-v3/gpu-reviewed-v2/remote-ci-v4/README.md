# Remote WebGL artifact preparation — v4 bounded diagnosis

This is a separate remote diagnostic recipe. It leaves production code, fixture math, screenshots, v2/v3 recipes, game budgets, and the phone/mobile performance claims untouched. It reuses the exact reviewed v2 viewer, GLBs, clip pack, and production import closure. The v4 immutable snapshot contains 36 files; the workflow template is excluded because it pins the manifest hash.

The v2 browser exceeded its 768 MiB diagnostic cap at 938,356,736 bytes before page readiness; v3 forced a single-process Chrome topology but still reached 861,863,936 bytes and exited at 5.957 seconds before completing screenshots. Those runs produced no complete frame set. V4 raises only this isolated remote browser-harness ceiling to 1,280 MiB so breadcrumbs can show how far the unchanged viewer progresses. The Node old-space cap remains 96 MiB, browser wall cap remains 60 seconds, and the build remains capped at 220 MiB process-group RSS / 25 seconds. This is a diagnostic observation limit, not a QA, gameplay, mobile, or product memory budget.

V4 preserves the four single-process Chrome flags used by v3: `--single-process --in-process-gpu --no-zygote --renderer-process-limit=1`. This deliberately nonstandard topology cannot represent normal multiprocess Chrome or mobile memory/runtime. The browser controller writes append-only JSONL stage records before/after Chrome launch, DevTools/CDP connection, navigation, viewer API/load, and every render capture. The Linux wrapper records the per-process RSS breakdown at the process-group peak and at the cap/timeout stop point alongside the aggregate RSS. Logs and breadcrumbs remain uploaded even on failure.

All visual/browser guards remain strict: same body/chart/topology checks, actual SwiftShader backend, no shader/runtime/console/network errors, exactly 12 matched screenshots, source hashes unchanged, and TERM-then-KILL cleanup. The fresh artifact prefix is `office-source-corner-gpu-v4-diagnostic-*`. A timeout, memory cap, incomplete frames, missing breadcrumbs, shader/error event, or source drift remains a failure; partial traces are diagnostic only and cannot be reported as successful visual evidence. Even a completed run would not establish mobile performance, battery, device memory, or visual acceptance.

The forced topology options are defined in Chromium's primary [content switch definitions](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/content/public/common/content_switches.cc). No local build, test, browser, server, workflow dispatch, push, or production integration was performed while preparing this folder. Root should review the exact snapshot and workflow pins before any publication.
