# GPU source-corner comparison — exact appearance replay (unexecuted)

This is a separate v3 fixture candidate. The v2 fixture remains unchanged and v4 remote failure receipts remain unchanged. No local or remote build, browser, test, server, or GPU execution has been run for this fixture.

## Why the previous raw-layout check failed

The shipped male and female GLBs use `KHR_mesh_quantization`: their raw `POSITION` accessors are unsigned 16-bit and their raw `NORMAL` accessors are normalized signed 8-bit. The v4 controller failed while comparing those raw attribute layouts directly with the current production actor. The actor is not in that raw state by the time the fixture captures it. `loadBody()` first creates the production wardrobe and applies its in-place body index mask, then `createAvatarAppearanceController().apply()` runs. The fixture's non-empty look omits expression; `normalizeLook()` resolves the recorded-look fallback to `smile`, and face defaults to `oval`. That appearance path replaces quantized position and normal attributes with Float32 attributes and calls `computeVertexNormals()`.

The normal check was therefore failing on a legitimate appearance transformation, not evidence that source vertex correspondence had changed. `BufferGeometry.computeVertexNormals()` iterates the geometry's full index attribute, not `drawRange`; production has already compacted retained indices in place and preserved the remaining tail. Replaying appearance against the raw full index would therefore create different normals from the displayed production body. The earlier v4 check stopped at `normal` before the later raw/current `position` constructor mismatch.

## What this candidate checks

The fixture copies the raw full GLB index and hashes it before any changes. On a private raw parse, it then installs a clone of the displayed production index array, draw range, and groups and invokes the same `createAvatarAppearanceController` with the exact normalized actor appearance. It requires the raw normal before replay to retain its expected quantized layout and the smile replay to yield Float32 position/normal attributes. After replay, it checks every raw/current body attribute's layout and bytes exactly, including position, normal, UV, color, skin indices, and skin weights. Bind mode, bind matrix and inverse, bone count/names/inverse-bind matrices, and mesh-local transform are also checked.

The private chart mesh is still cloned from the actual displayed body geometry, so it keeps the exact appearance-shaped positions, current normals, other attributes, skeleton, and bind state. The chart builder replaces only that private clone's index with a copy of the separately saved full original GLB index. The displayed production body's mask bytes and draw range are snapshotted and checked unchanged after chart construction. Existing CPU-reviewed triangle and vertex counts remain hard guards: male 3,266 triangles / 1,778 vertices; female 3,541 / 1,893; original full body index 9,002 triangles. Any mismatch fails closed; no normal or position comparison was relaxed.

This preserves the production face expression and verifies exact correspondence after replay rather than forcing a neutral look or skipping the normal guard. It remains an unexecuted source candidate; the custom source-corner GPU shader changes position skinning only and standard skinned-normal behavior is still unverified. A future remote recipe must include the separately reviewed bounded RSS monitor race fix; this README does not claim that recipe is ready or that any visual result exists.
