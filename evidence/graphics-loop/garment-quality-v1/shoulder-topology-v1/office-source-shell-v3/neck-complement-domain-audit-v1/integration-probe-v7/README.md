# Neck-complement GLB request-lifecycle diagnostic v7

V7 preserves the v6 candidate geometry, source-body mask, shader adapter, and strict matched-render guards. V6 completed 60 image captures and 16 exact-position pose witnesses, but failed the final network gate on three canceled GLB requests (`clip-pack.glb`, male body GLB, female body GLB). The artifact did not retain request initiators, response/finish state, or timing, so it did not establish whether these were duplicate verification-versus-loader requests, actual body-load cancellations, or another cause. V7 adds only diagnostic instrumentation and synthetic lifecycle tests; it does not suppress, whitelist, or reinterpret failed requests.

The fixture records browser-side load generations and events around explicit asset verification, `loadBody`, chart construction, body switching, and disposal. CDP records each GLB URL, request/loader/frame IDs, initiator stack, redirects, response status, `Network.dataReceived` byte chunks, `loadingFinished` or `loadingFailed`, cancellation/error details, and both CDP and controller timestamps. A manual fetch still records the verified response byte count and SHA. The final gate remains fatal on any failed request or GLB request still pending. This should identify the initiator/lifecycle correlation without changing time or memory caps.

The remote workflow retains the existing 96 MiB Node heap, 220 MiB build/test process-group RSS and 25-second bounds, and 2 GiB browser RSS and 60-second bound. The existing 60-frame and 16-pose schedule remains unchanged, so this run is diagnostics-only and could still hit the existing browser cap. No local test/build/browser run has been performed for v7. No production code or geometry was changed, and no render or graphics acceptance is claimed.
