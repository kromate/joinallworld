## Execution and preservation

Use the original admitted configuration and its exact tooling/runtime pins.
Existing incompatible bindings refuse; do not migrate a binding, replace a
namespace, delete sidecars, or reset spent acquisition/indexing budgets.
`FeatureIndexSession.auditCaptures(inputs, attemptLimit)` is one final call under
the same paired leases. Inputs must include every durable capture, sorted by
request hash, with immutable raw paths/expectations and declared required contexts.
After its terminal result, close the session; further ingestion or another audit
in that session is refused. A later admitted audit-only session may replay the
saved result without a new audit attempt after revalidating retained evidence.

The controller derives allowable observation pins from settled durable attempts.
A pin is not proof of campaign membership. Fixed workers compare raw ordinals
and SQL in both directions using an explicitly charged private DB/WAL snapshot.
Original database/sidecars, raw captures, binding, locks and capture controls are
checked before and after. Reservations reside in the namespace registry, not a
required `reservation.json` in each index. Optional child metadata is still
preserved and checked for appearance/mutation.

Keep limits unchanged:256 capture calls,16 admission attempts,8 capture/audit
attempts,128,000-byte frame and512,000-byte audit-envelope ceilings. The input
count cap does not guarantee the encoded corpus fits. Each source/configuration
file is rounded to8KiB for preflight, with actual allocation checked independently.
The47-file closure currently allocates892,928B; registry controls including its
optional operation fill the existing1,048,576B allowance. Any growth crossing
that allowance must refuse, not enlarge it. Retain actual child handles and
scratch if termination is unconfirmed; never kill a process from a remembered PID.
