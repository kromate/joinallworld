# geoBoundaries global ADM1 metadata catalogue

This is a bounded discovery snapshot of the official [geoBoundaries current gbOpen ALL/ADM1 API](https://www.geoboundaries.org/api/current/gbOpen/ALL/ADM1/). It is not geometry acquisition, source admission, license verification, or a claim of global boundary completeness. The captured response is retained outside the game at `.cache/world-build/fine-catalogue-cache/all-adm1-metadata.3c742bab8428c987437e48dc5a9a6df826d5b47d3e06c613356733bd4ce3da98.json`; the fsynced start and terminal events and separate stdout/stderr are alongside it in that cache directory.

The one request returned HTTP 200 in 2,003 ms with 350,392 response bytes, `Content-Encoding: identity`, ETag `"558b8-6121e2f267d23"`, and Last-Modified `Sat, 24 Feb 2024 10:31:49 GMT`. SHA-256 is `3c742bab8428c987437e48dc5a9a6df826d5b47d3e06c613356733bd4ce3da98`. The durable start reserved the full 2,097,152-byte response cap before network access. Terminal evidence records 0 unknown response bytes and 0 reserved bytes after the measured successful response. Cache use was 0 bytes before capture, below the 10 MiB cache cap; available disk was 41,783,283,712 bytes against the 100 MiB minimum. No retry, geometry URL, source archive, or Git object was fetched.

`fine-catalogue-sources.json` freezes the metadata response pin and expected record count of 199. The body is a JSON array of 199 objects with 32 keys in the sampled record. The report builder validates the exact body hash and byte count and retains every input row. Required descriptive fields were present as nonempty strings on all 199 rows, including `boundaryID`, `boundaryISO`, `boundaryName`, `boundaryType`, `boundaryCanonical`, `boundaryYearRepresented`, `boundarySource`, `boundaryLicense`, `licenseSource`, `gjDownloadURL`, `admUnitCount`, and `buildDate`. All 199 `boundaryType` values say `ADM1`; one row (ordinal 78) has the inconsistent identifier `IND-ADM0-90661403`, so it is counted and reported as invalid rather than silently reclassified. All reported unit counts are digit strings; their metadata sum is 3,281. Twenty layers exceed the proposed 32-unit pilot cap and remain in the report, including Nigeria (37 units). Candidate release strings are only seven-character prefixes embedded in GitHub URL paths; this work does not resolve or pin those commits.

The pure `buildFineCatalogue` report matched candidate ISO3 values only through the exact source feature references in the current 1:110m Natural Earth coarse inventory. That inventory has 177 source units and 177 country nodes, including Nigeria’s protected `legacy-ng` node. Results: 167 metadata layers linked to existing source-backed country identities, 30 valid metadata layers had no coarse country counterpart, one metadata row was invalid, and one layer remains linked to protected Nigeria. Of 177 coarse country nodes, 167 link, nine have no metadata row, and Nigeria remains protected; none is ambiguous in this snapshot. The apparent difference between 30 unlinked metadata layers and nine coarse countries lacking a metadata row reflects the two different denominators. The nine coarse names without a metadata layer are Western Sahara, Falkland Islands, French Southern and Antarctic Lands, Puerto Rico, New Caledonia, Antarctica, Northern Cyprus, Somaliland, and Kosovo. These are source-coverage exceptions, not legal or sovereignty findings.

Metadata license and source descriptions are carried verbatim as supplied. They are hints for later per-source review, not permission or proof that a geometry file has matching terms. A future pilot needs a separately pinned geometry payload, independently checked feature count and identity properties, byte and coordinate caps, exact country-link validation, and a source-specific license/attribution decision before any publication. `buildFineCatalogue` neither downloads candidate sources nor claims all countries, settlements, or playable content are represented.
