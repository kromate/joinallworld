# Finer geographic inventory: source contract and Ghana pilot

This is the next-source contract, not a claim that the pilot data has been downloaded or accepted. It extends the coarse inventory without changing existing country IDs or the protected Nigeria provider. `inventory.ts` currently accepts only world/continent/country nodes (schema 1); `world/types.ts` already names `admin` and `city` as region kinds, but that does not make them inventory node kinds. The ROLLOUT contract calls for release-pinned administrative layers, typed units, aliases/tombstones, and explicit source coverage.

## What the sources actually cover

Natural Earth 10m is a cartographic selection. Its official catalog describes Admin-1 as over 4,500 state/province divisions, Admin-2 as counties limited to the United States, and populated places as selected city/town points. Its populated-place method includes every Admin-0 capital, many (not every) Admin-1 capitals, major cities/towns, and a sample of small towns in sparse areas; it favors regional significance over census completeness. Thus neither the source feature count nor its population attributes is an “all cities” denominator. Natural Earth says its default borders are de facto and offers worldview variants; the base inventory must record that policy rather than adjudicate sovereignty. [10m cultural catalog](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/), [populated places selection and caveats](https://www.naturalearthdata.com/downloads/50m-cultural-vectors/50m-populated-places/).

Natural Earth is public domain, including commercial use; attribution is optional, though the project can retain its existing attribution. Its 10m Admin-0 catalog distinguishes 258 “countries”/map units from sovereignty and map-subunit products, so do not silently replace the existing 110m country denominator/IDs with a different theme. Small/micro territories vary by scale and theme: retain each source’s own denominator and make unmatched existing countries/territories explicit exceptions; do not call source absence real-world absence. [Terms](https://www.naturalearthdata.com/about/terms-of-use/), [10m Admin-0 theme distinctions](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/).

geoBoundaries exposes per-country and `ALL` endpoints for `gbOpen`, `gbHumanitarian`, and `gbAuthoritative`, and boundary levels ADM0 through ADM5. Its API says gbOpen is CC-BY 4.0 compliant generally; metadata separately reports each layer’s original `boundaryLicense`, source and license URL. Those per-layer terms must be retained and reviewed; do not assume “open” overrides an upstream share-alike or other condition. The API’s `boundaryID` is for a layer (country + level + generated unique value) and changes when underlying data changes, so it is a **release-qualified source reference**, never the durable game/admin ID. Its metadata returns `admUnitCount`, represented year, build date, sources, license details, download links and simplification link. [API contract and archive access](https://www.geoboundaries.org/api.html).

The official current Ghana ADM1 metadata endpoint currently reports `GHA-ADM1-69750345`, canonical type `Region`, represented year 2021, 16 units, primary source OpenStreetMap, original license `Creative Commons Attribution-ShareAlike 2.0`, and a GeoJSON URL under repository commit prefix `9469f09`. This is discovery evidence only. Before the pilot, resolve that prefix to a full immutable Git commit, pin the commit-addressed raw GeoJSON URL, then calculate and check in the downloaded byte count and SHA-256. Do not pin `/api/current/` as the build input, treat the abbreviated hash as immutable, or invent the content hash now. [Ghana ADM1 metadata](https://www.geoboundaries.org/api/current/gbOpen/GHA/ADM1/).

## Identity and hierarchy contract

Keep existing Natural Earth country IDs byte-for-byte as generated today, including `legacy-ng`; do not renumber a country because an ADM source has a different border, country spelling, or ISO representation. New admin/city nodes use internal IDs owned by this project. Suggested shape (proposal only):

```ts
type FineNodeKind = 'admin' | 'city';
type AdminLevel = `ADM${1|2|3|4|5}` | 'natural-earth-admin1';
interface FineNode {
  id: string; parentId: string; kind: FineNodeKind; name: string;
  countryId: string; countryCode: string | null;
  adminLevel?: AdminLevel; adminType?: string; // source's actual canonical label, e.g. Region
  sourceRefs: Array<{sourceId:string; release:string; layerId:string; featureKey:string}>;
  aliases: string[]; bounds: Bounds | null;
  outline: 'available'|'missing'; exceptions: string[];
}
interface CoverageRecord {
  sourceId: string; layerId: string; expectedUnits: number | null;
  assignedUnits: number; rejectedUnits: number; exceptions: string[];
}
```

This shape is intentionally narrower than the existing inventory schema; implementation should introduce a new version/compatible extension rather than loosen schema-1 validation in place. `parentId` for admin-1 is the already-existing country game ID; deeper levels parent to their immediate lower level. Never infer that level labels mean “state,” “province,” “county,” or “LGA” globally: keep source `boundaryCanonical`/level and local type/name as metadata. Admin-feature identity cannot be `boundaryID` alone. After downloading a pinned layer, inspect its properties and choose the strongest provider feature identifier; if none is stable/documented, mint an internal ID from the canonical country game ID + source layer identity + normalized feature key, and treat changes as reviewed alias/tombstone migrations. Names/slugs are display aliases only, not unique IDs. Duplicate identifiers, splits, merges, renamed units, and unmatched units must stop publication or become explicit reviewed migration records.

For Natural Earth country linkage, map Admin-1 parent to the **existing** country using a verified source country code/identifier mapping, not a fuzzy name join. Natural Earth `NE_ID` and its present game IDs remain the current country identity. For geoBoundaries, country ISO alpha-3 is a candidate mapping aid, not itself the game's country key. Require one parent resolution per admitted feature; ambiguous/unmatched features count in `rejectedUnits` and block a “complete” pilot. Disputed geography is source-described: store dataset release, worldview/boundary policy and any source exception; never portray a boundary as a legal conclusion.

City nodes are a separate point-directory coverage tier, not children implied by every admin polygon. A city source must publish its selection method/denominator, time/version, feature identity policy and omissions. For Natural Earth populated places, define coverage as “all rows in pinned Natural Earth populated-places extract after declared filters,” report row/accepted/rejected counts, and label the result selected places. Do not infer that each administrative unit has a city, nor claim “all cities,” complete census population, or complete Admin-1 capitals.

## Bounded Ghana ADM1 pilot acceptance

Use Ghana (`GHA`) gbOpen `ADM1` only, with the current metadata above as a candidate. Preserve the coarse inventory’s source pin, country IDs and Nigeria legacy provider. No Admin-2, cities, all-country endpoint, simplification, auto-update, or additional source download belongs to this pilot.

Before fetching geometry, save the API JSON as small discovery evidence (maximum 64 KiB), validate required metadata fields, resolve the metadata commit to a full 40-hex commit, and construct the fixed commit-addressed GeoJSON URL. A coordinator-reviewed source pin must then contain URL, full release/commit, source represented year/build date, upstream source/license URL, attribution text, byte count and computed SHA-256. Verify licensing against the source terms and intended distribution; do not redistribute or admit derived geometry until that license gate is resolved. Stop if the metadata moved between review and fetch, the commit cannot be resolved, licensing is ambiguous, redirects escape the approved GitHub host, or any pin field is missing. API/current is never an input at compile time.

Admission limits for the one-file pilot: compressed/network body at most 8 MiB; decompressed input at most 32 MiB; feature count 1–32 (expected metadata count 16); total coordinate positions at most 150,000; one geometry feature at most 40,000 positions; published inventory output at most 16 MiB; elapsed fetch/parse/build 120 seconds; no retries beyond one manually reviewed retry; no unbounded archive extraction. These are guardrails, not predictions of actual file size. Stream/count bytes before parse; reject duplicate JSON keys if the parser supports detection, non-FeatureCollection input, non-Polygon/MultiPolygon geometry, nonfinite/out-of-range/unclosed rings, duplicate source identifiers, malformed CRS (only WGS84 longitude/latitude accepted), and features exceeding bounds. No feature is silently dropped. Verify exact equality between metadata `admUnitCount` and source feature count, and conservation: accepted + rejected = source count; pilot success requires rejected = 0, all 16 (metadata-verified) features assigned once, and all parents resolved.

Retain every source property needed for the selected stable feature key, official/local name, source canonical type, and aliases with source provenance. Record each per-feature mapping and any duplicate/renamed match against previous inventory. Emit a coverage report with source layer ID, represented year, original license, count denominator, assigned/rejected counts, parent-resolution counts, and exceptions. Store immutable input and output by SHA-256; publish manifest last. A repeated run on identical input and tool version must yield the same canonical inventory/manifest hash. A failed or incomplete pilot must not publish a success manifest or change existing country inventory.

Tests required before admission: pinned metadata schema/required-field tests; fixture with 16 synthetic-valid feature records to prove conservation and deterministic IDs; duplicate/missing feature key, wrong parent, count mismatch, invalid polygon, coordinate/byte cap, redirect/host rejection and licensing-metadata absence all fail closed; a rename/split fixture requires explicit alias/tombstone mapping; existing coarse inventory snapshot asserts all country IDs—including `legacy-ng`—unchanged. No test should use a newly downloaded or fabricated Ghana boundary checksum as if it were real.

## Remaining decisions before data admission

This research did not download the candidate GeoJSON and cannot verify its true properties, byte size, geometry validity, per-feature IDs, full commit hash, SHA-256, or whether current metadata still matches at execution time. Those are required pin/review outputs, not assumptions. The OSM-derived CC BY-SA 2.0 source needs lawful-license verification for the intended distribution; no redistribution or geometry admission until that gate is satisfied. If unresolved, select a differently licensed gbOpen country layer only after metadata and license review. For global rollout, define a country/territory denominator and explicit no-ADM1/contested/special-region policy before reporting completeness; geoBoundaries supports varying levels and availability, not a universal one-to-one state/province model.
