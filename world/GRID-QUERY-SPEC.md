# Country-grid source-query campaign, schema 2

This additive stage reuses `runCampaign`, its shared source-cache lock, resource reservations, durable usage/stage journals and existing SQLite `Ledger`. Historical schema1 configs/results/request hashes remain unchanged. There is no second scheduler. Schema2 requires `inventoryKind:country-directory`, the exact directory hash, a completed immutable country-grid plan hash, and every selected root cell. Builder state remains separate from the game and protected Nigeria.

## Identity and graph

`grid-query-types.ts` freezes the shared contract. A root address is `{rootCellId,path:''}`. Child digits0/1/2/3 mean southwest/southeast/northwest/northeast, respectively. Bounds are exact dyadic halves of the original geographic root bounds. A child ID is `<root>:q<path>`, while the root keeps its original ID. Query bounds are closed for source intersection; adjacent queries may overlap on their boundaries. Country membership and unique-feature ownership are not established by a query. CountryCode may be null; timezone remains unknown.

Grid binding schema1 pins the full canonical plan-file SHA256 PLUS newline, not the request hash, maxDepth0..8 and maxJobs1..400,000. maxJobs includes roots and all retained subdivided parents/children. Root priorities follow the original numeric grid order; descendants inherit root priority. Factory and claim verification reuse a validated immutable root resolver snapshot so they do not hash the entire grid once per cell. The complete source grid remains immutable with every original cell not-started: query state lives only in its campaign.

The query campaign schema2 has strict id/inventoryHash/inventoryKind/gridQuery/units/limits. Only grid-query units are accepted. Claims pin campaign hash, directory hash and the complete derived unit. Descendant payloads are deterministically reconstructed from the root template and address. Foreign roots, changed bounds or source layers, missing roots, changed priorities and schema1 substitution fail closed. Config output is capped64MB; grid and acquisition limits remain their existing tighter bounds.

A separate local `grid-query-binding.json` pins canonical plan path/hash and source cache root. Production uses the world-build acquisition root; injected tests use the dedicated campaign source-cache. Changing modes or paths is not allowed. The plan loader requires the existing exact plan AND completion before calling the resource-isolated grid publisher for an exact verified cache hit; it does not repair/create missing plans. The full country directory/hierarchy and source pins are verified. Production paths must stay in this isolated worktree's world-build cache; test paths are canonical dedicated temporary trees.

## Acquisition failures and atomic subdivision

Successful acquisition request/receipt/cache identities keep `world-source-compiler-v2`. Network byte and disk accounting still occur under the existing shared acquisition lock. Each attempt reserves before dispatch; opaque/killed/HTTP/transport/deadline/network/disk/validation failures retain conservative full reservations and never trigger subdivision by matching text.

Only a normal adapter exit3 with exact JSON `{schemaVersion:1,kind:'budget-exceeded',reason,networkBytesMeasured}` admits typed failure. Reasons are exactly selected-item-count, feature-row-budget and geojson-output-bytes. Measurement is a nonnegative safe integer not above the admitted cap. Python emits this only after response accounting is settled and no proxy diagnostics remain. The three typed producer sites are all BEFORE extract or receipt writes; feature-row failures close the DB/proxy and join first, output-byte failures occur after in-memory serialization but before staging output, and selection-item failures precede querying. Node removes private staging before rethrowing. Source-index growth is still measured separately. Thus this admitted prepublication contract permits measured network charging and zero published input/output charging; it is not an inference from network bytes alone. Generic failure shapes and historical audit bytes remain unchanged. New typed audit records retain the full reservation upper bound alongside measured bytes/failureKind.

A typed density failure may create exactly four deterministic children if depth and total job caps allow. `Ledger.completeAndEnqueue` validates the entire batch, verifies a live parent lease, checks exact existing child identities and atomically inserts all children plus completes the parent. Any conflict rolls back everything. Stale leases change nothing. A completed subdivision without all four jobs is corruption; an orphan child or child of a non-subdivided parent is rejected. Reaching subdivision caps makes that query an explicit terminal exception rather than repeatedly consuming density attempts.

## Captures and coverage

A query-captured result pins exact extract and immutable original receipt bytes/hash, request identity and supported feature-row count. Both run/resume and status reverify source/receipt integrity; damage fails closed without reacquisition or silent repair. Metrics/upstream/exceptions are bounded and compared against the original receipt, allowing the existing verified cache semantics: zero new network, fresh elapsed time and empty new upstream list. Zero supported features is an accepted source-query result, not a claim of physically empty geography. It does not enter compile/validate geometry stages or bypass the old zero-tile rule.

`queryCoverage` schema1 reports source-query-only/not-compiled, fixed root denominator, captured/exception/pending roots and total/subdivided/captured/zero-supported/failed/queued/leased jobs. A root is captured only when all descendant leaves are captured; any failed leaf makes it an exception; remaining pending leaves remain pending. Missing root records remain pending. SupportedFeatureRows sums accepted leaves, which may overlap; it is never a unique building count. Existing compiled count stays0 for every schema2 campaign. A terminal query campaign means its admitted source-query work ended, not country geometry, world, exploration or playability completion.
