# Independent world foundation: binding implementation spec

8 October 2026. Baseline game commit 4832b7e7507914db8a4d721a7f6e5d6ad21d91e1.

## Scope and boundary

Build runnable, tested tools under `world/` only. Do not modify `src/`, `server/`, `deploy/`, game databases, Nigeria packs, shared city catalogue, root dependencies or budgets. Build products live under this worktree's `.cache/world-build/`. This is an independent preview/compiler, not a production integration or a declaration that every country is playable. No paid calls, new cloud services or automatic publishing. No country-level humidity preset: climate is sourced monthly regional data; missing data stays missing.

The first milestone is reproducible GeoJSON -> lightweight pack -> separate browser preview, with resumable jobs and immutable publication. The runner must be able to operate without AI. Luna implements software and later fills bounded evidence-backed descriptive fields; geometry, measurements, IDs and weather do not come from a language model.

## Frozen interfaces

`types.ts` is owned by the coordinator. All geographic positions are WGS84 longitude then latitude; local scene axes east, up, negative north in metres. Heights in the frame are ellipsoid heights, not unconverted DEM orthometric elevations. The current compiler uses height zero for the ground and records terrain unavailable. Preserve source IDs, distinguish estimated heights, preserve polygon holes. Frame origins are per tile, not per continent. No implicit Nigeria adapter or migration in this milestone.

Manifests explicitly distinguish foundation from explorable; playable is deliberately unavailable until a later authoritative gameplay adapter is reviewed. A null climate or timezone is unknown, never inferred from country/continent. A source checksum describes exact input bytes and all sources carry URL, release and licensing. Source IDs must resolve. File names are content hashes. Unknown schema versions fail closed. Reject nonfinite coordinates, malformed/degenerate rings, invalid timezones, duplicate IDs and oversized packs. Rendering must also cap the total visible workload; per-tile gates alone are insufficient.

## Six Luna implementation lanes

1. **Geography and conditions** owns `geo.ts`, `conditions.ts` and their tests. Provide WGS84 ECEF <-> local ENU using scene axes above, polar/dateline support, local range documentation, deterministic local clock via Intl IANA timezone, approximate solar altitude/daylight, sourced climate lookup and stale live-weather fallback. Export `toLocal(position: Anchor, origin: Anchor): {x:number,y:number,z:number}` and `fromLocal(local,origin): Anchor`. Export `localClock(epochMs,timezone)` and `solarAltitude(epochMs,latitude,longitude)`. No game imports or random/time reads. Validate against independent known locations and reference vectors, London DST and polar solstices.
2. **Pack contract and packaging** owns `validate.ts`, `pack.ts` and tests. Export `validateTile(value:unknown): WorldTile`, `validateManifest(value:unknown): WorldManifest`, `canonicalJson(value:unknown):string`, `sha256(bytes:string|Uint8Array):string`, `encodeTile(tile:WorldTile):{ref:TileRef,bytes:Uint8Array}`, `encodeManifest(manifest:WorldManifest):{hash:string,bytes:Uint8Array}`. `encodeTile` path is `tiles/<sha256>.json`, raw JSON bytes with separately measured Brotli size. Validate before encoding, actual geometry complexity conservatively accounted. Browser validation must not import node builtins. Root types are frozen; request changes through coordinator.
3. **Durable queue and output protection** owns `ledger.ts`, `storage.ts` and tests. Node built-in SQLite with immediate transactional claims, leases, monotonically changed tokens, bounded retries, resume, duplicate job payload mismatch rejection. Export class `Ledger(path)` with `enqueue({id,kind,inputHash,payload,maxAttempts})`, `claim(worker,now,leaseMs)`, `heartbeat(id,token,now,leaseMs)`, `complete(id,token,now,result)`, `fail(id,token,now,error,retryDelayMs)`, `list()`, `close()`. Claims expose id/kind/inputHash/payload/attempt/token/leaseUntil. Times injected milliseconds. `storage.ts` export `createOutputStore(root,allowedRoot)` yielding async `writeImmutable(relativePath,bytes)` and `writeAtomic(relativePath,bytes)`; enforce canonical containment and reject symlink escapes, absolute and traversal paths, repo/game/database directories outside dedicated output root. Hashes verified on immutable collision. Publication manifest last, never partial completion. SQLite is local disk only; multi-machine queue later.
4. **Source compiler** owns `ingest.ts`, `sources.ts`, source fixtures and tests. Consume bounded GeoJSON building polygons/multipolygons and road lines with pinned SourceRecord; deterministic sort/part IDs, honest defaults, reject Nigeria regions by country code, no network in compiler. Export `compileRegion(region:Region,source:SourceRecord,geojson:unknown):{manifest:WorldManifest,tiles:WorldTile[]}`. Subdivide spatially until budgets pass, reject individual oversize features rather than claiming coverage; crossing/duplicated geometry and holes handled. Public source download must be bounded, checksum verified, explicit URL; Overture acquisition recipe pins release and intersects bbox, never selects by centroid alone. No runtime GIS dependencies. No invented pilot facts: synthetic fixtures labelled test-only, actual source extracts labelled accurately.
5. **Streaming preview** owns `preview/` and tests for any pure cache model. Standalone Vite/Three.js entry with own config, no gameplay imports. Input manifest URL from explicit local build output served via narrowly scoped middleware. Tile fetching concurrency <=2, abort obsolete requests, bounded resident budget <=90k triangles/40 calls, disposal, manifest-hash version pinning, integrity verification, safe error/unknown states, source attribution, estimated height labels, no claims of photorealism. Render building holes and roads in local metre coordinates; daylight/time controls. Clear visual progress/loading and total measured bytes. Usable narrow viewport and keyboard controls. No huge global catalogue. Demo synthetic clearly labelled unless a pinned real extract is supplied.
6. **Runner and integration QA** owns `cli.ts`, `pipeline.ts`, `integration.test.ts`, `tsconfig.json`, `README.md` and continuation docs. Integrate prior exports; standalone commands `node --experimental-strip-types world/cli.ts ...`. One heavy job at a time; plans contain region + source + local input; verify source hashes and size, total input/output caps and max run duration. Use deterministic job identity including source, config, compiler/schema. Build to immutable files, write manifest last, validate before complete. Resume must verify published output; corrupted/missing completed outputs cannot be silently skipped. Reject Nigeria and all outputs outside dedicated root. A fail/continue status report must expose failures; CLI nonzero on failed work. Support status and bounded run; no shell-command or model execution from a job payload. Tests cover deterministic rerun, interruption/lease loss, corruption, path escape, budgets and isolation. README exact runnable commands, no global completion claims.

Three workers maximum concurrently in this session, six lanes in two waves. Workers run focused tests; coordinator runs world typecheck, all world tests, compiler/preview smoke and isolation check. Do not run expensive main game checks simultaneously. No new dependency required; reuse installed TS/Vite/Three for tooling/preview only.

## Decisions resolving research questions

- Coordinates: local WGS84 topocentric rather than extending the Nigeria flat frame globally. PROJ documents ECEF -> ENU and EPSG:9837: https://proj.org/en/stable/operations/conversions/topocentric.html . Typical tile extents remain small; world navigation uses geographic bounds. Never claim flat rendering suitable at continental street scale.
- Time: IANA Intl display handles DST; solar position is approximate NOAA equations with explicit polar cases: https://gml.noaa.gov/grad/solcalc/solareqns.PDF . Gameplay clock changes are deferred because they would touch Nigeria rules.
- Queue: built-in Node SQLite available on project's Node >=22.18; BEGIN IMMEDIATE protects claims, short transactions, local WAL, FULL synchronous where crash durability matters. https://nodejs.org/api/sqlite.html and https://www.sqlite.org/lang_transaction.html . Fenced tokens prevent stale workers completing reclaimed jobs; immutable output + manifest-last makes retries safe.
- Source acquisition: Overture bbox-overlap predicate (`xmin <= east AND xmax >= west AND ymin <= north AND ymax >= south`) followed by geometry filtering; split antimeridian query. Freeze a release from STAC during planning then persist it; never resolve latest during resume. https://docs.overturemaps.org/getting-data/duckdb/ . Bounded GeoJSON compiler allows first real pilot without shipping DuckDB in game or taking on a planet download.
- Efficient generation: deterministic compilation is the cheap bulk worker. Models are not one call per building. Later enrichment is optional structured evidence-only output keyed by source hash/model/prompt version, with token/cost caps and no arbitrary executable code.
- Data distribution: own immutable content-addressed JSON tiles first; PMTiles only if measured vector atlas needs justify it. External storage, CDN and Range/CORS gates belong to a later deployment task. No external storage chosen or billed here.
- Climate: missing source means unavailable, not a fabricated climate. Regional monthly profiles; future ERA5 extraction must pin period/grid/variables and explicit elevation treatment. Africa is climatically diverse and Antarctica cannot use Web Mercator-only coverage.
- Transport: no all-pairs generated world links. Future route provider uses sparse sourced road/ferry connectivity and separately verified flight routes; current Nigeria travel unchanged.
- Completion: job success means emitted validated pack, not surveyed city or full playable world. Coverage exceptions and unknown climate/terrain must be visible.
- Concurrency: worktree output, standalone module boundary, no game database access; eventual adapter is a separate reviewed diff after both workstreams stabilize. Full multi-region game server scaling is not silently bundled into world-data work.

## Subsequent acceptance milestones

M1 this runnable independent foundation. M2 pinned real pilots Accra/Nairobi/Cape Town plus preview-only London and Antarctic cell, terrain and monthly climate ingestion, network + low-end-device benchmarks, licensed distribution evidence. M3 Africa foundation batch with source-unit denominator and exception report. M4 approved reader/gameplay adapter with existing Nigeria saves/routes/startup tests, then staged continent rollout. Photoreal assets remain optional representations attached to stable IDs; no whole-world 48-hour quality guarantee before measured throughput.
