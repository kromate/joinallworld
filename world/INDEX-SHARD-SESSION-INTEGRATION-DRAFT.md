# V3 shard session integration draft

Status: design only. The V3 batch admission worker exists, but the capture and audit session still admits one V1 index. This draft describes the next integration; it makes no completion or coverage claim.

## Existing boundary

`index_registry_controller.restartable_registry_startup(..., _plan_input=...)` performs one durable FORMAT_V3 `admit-plan` attempt for the entire frozen plan. Its fixed worker opens the namespace registry, atomically reserves the full batch, publishes and verifies all child bindings, closes SQLite, and returns a bounded `shardAdmission` receipt. The controller retains a namespace lease through return only when its caller passed `_inherited_lease`; its default lease scope closes before return. The existing `supervised_charged_index()` caller owns and passes that lease, which is why its yielded session retains it. A shard session must follow that explicit inherited-lease pattern and must not reopen the registry database in its parent process.

The V1 `capture_session()` path in `tooling/index_admission.py` calls `supervised_charged_index()` once, requires `registry.admission`, and yields one V1 `ChargedIndexRoot`. It allows at most 256 capture calls and one final audit. `feature-index-session.ts` mirrors that single-index protocol and its 600,000 ms session deadline, 128,000-byte line bound, 96 MiB Python coordinator RSS ceiling, and bounded output. Keep that wire and behavior byte-compatible for V1 callers.

The plan worker's `shardAdmission` is the only namespace-level admission receipt needed by the next session. `index_admission_worker.shard_admission_summary()` checks the complete planned root/binding/lock set without SQL. Existing `index_root.precharged_index_shard_root()` is unsuitable for a session handoff because it needs a live `IndexReservations` connection and `_namespace()` performs SQL checks. Add a distinct plan-authority-gated child opener that validates the held namespace lease, the V3 receipt and exact plan membership, then takes one child lease and verifies that child's admitted root, lock, and V2 binding. It must do no parent SQL. The existing V1 opener and decoders remain V1-only.

The existing Python entry points for capture, ingest, and audit call `decode_index_binding()` directly. Add explicit planned-shard entry points or pass an internal admitted-shard object carrying the already validated plan authority and child index identity. Do not broaden `decode_index_binding()` to accept V2. The fixed bootstrap, ingest, and audit workers must receive the expected child identity through a bounded explicit mode and independently verify the exact V2 binding under their existing worker guards.

## Durable multi-window lifecycle

The supported campaign plan can contain 4,096 request units. A 256-call, 600-second session is a processing window, not a maximum batch size. The immutable full plan is admitted once, then capture and audit work runs through as many sequential bounded windows as needed. Sixteen full capture windows cover 4,096 units; any partial final window is derived from the same sorted plan. Window boundaries do not create namespaces, registry admissions, or new retry allowances.

Persist the canonical plan bytes in campaign-owned state, not in the namespace's 1 MiB registry-control allowance. Use one immutable `feature-index-shard-plan.json` pin `{sha256,bytes}` with `bytes <= 2 MiB`, and one atomic private `feature-index-shard-admission.json` receipt with this exact v1 shape:

```json
{
  "format": "campaign-feature-index-shard-admission-v1",
  "campaignHash": "<sha256>",
  "plan": {"sha256": "<sha256>", "bytes": 1},
  "baseBinding": {"sha256": "<sha256>", "bytes": 1},
  "sourceConfiguration": {"sha256": "<sha256>", "bytes": 1},
  "toolingManifest": {"sha256": "<sha256>", "bytes": 1},
  "namespace": {
    "rootDevice": 0, "rootInode": 1, "lockDevice": 0, "lockInode": 1,
    "aggregateBytes": 17825792
  },
  "controllerRecord": {"sha256": "<sha256>", "bytes": 1, "attempts": 1, "attemptLimit": 16},
  "shardAdmission": {
    "planHash": "<sha256>", "shards": 1, "reservedBytes": 65536,
    "rootIdentitySha256": "<sha256>"
  }
}
```

These numeric values illustrate field shape only; validators use the actual strict V3 and plan bounds. Publish the receipt only after the full plan admission is terminal and verified. It is immutable: every later window compares it byte-for-byte/canonically with the same plan, base/source/tooling pins, V3 controller record, namespace identity, and `shardAdmission`. The campaign's existing ledger rows remain the per-capture progress record; do not add a mutable PID/owner file or treat a saved window cursor as authority. Derive each next capture window from the sorted pinned plan and currently token-fenced completed index rows. Recheck the exact source capture and raw/receipt pins before dispatch. A Python terminal capture whose campaign token is stale is not campaign completion; reclaim and replay that same row under a current token.

Each window begins by acquiring the actual namespace writer lock on the recorded namespace and lock inodes. A successful exclusive kernel lock on that same lock inode, followed by identity checks, proves no other holder still owns the namespace; a stored PID or stale process record does not. Then verify the original V3 record is terminal for the exact `admit-plan` operation, its successful initialized-registry witness is intact, and its recorded plan/base pins match. Do not call `restartable_registry_startup()` to reopen a completed admission: its normal recovery path can prepare another controller attempt. Revalidate the persisted `shardAdmission` and all child roots/bindings/locks under the held namespace lease. The registry reservation set also needs an explicit bounded fixed-worker verifier under the existing worker caps; the Python coordinator must not open SQLite. This verifier is read-only, does not reserve again, and does not consume a V3 controller attempt.

Keep the namespace lease only for one bounded window, release it after all child workers have confirmed terminal cleanup, and reacquire it for the next window. If the coordinator dies, kernel lock release (or continued ownership by a surviving child) controls when another window may proceed. If the namespace path or `writer.lock` was replaced, device/inode checks fail before any capture, audit, or registry mutation. The plan, V3 attempt count, aggregate charge, child bindings, and original campaign retry limits remain unchanged across all windows.

Schedule audits with one deterministic audit Ledger row per planned shard, each bound to the immutable batch plan and exact shard membership and each using the original frozen `maxAttempts` (which must be at most eight). A bounded session can audit only the shards that fit its 256-operation, line/output, and 600-second limits; the next audit window resumes other shard rows. Previously completed shard audit records are revalidated and skipped without consuming a retry. Only a final aggregator can publish campaign audit completion, after all expected shard rows are complete and the disjoint shard request/observation unions equal the original fenced campaign denominator. Per-shard SQL totals remain shard-local and cannot be summed as globally distinct totals.

## Proposed session interface

Add a distinct `openFeatureIndexShardSession(config, planPin, operationWindow, options?)` and Python CLI mode, for example `--shard-capture-session`. Init carries the unchanged V1 base binding, source/runtime pins, namespace root and aggregate, the frozen full-plan pin, the immutable admission receipt, and an explicit bounded operation window. Keep V1 `openFeatureIndexSession()` and `--capture-session` unchanged.

The full plan is bounded to 2 MiB and does not fit the existing 256,000-byte init frame or 128,000-byte line. Send it through ordered bounded chunks with acknowledgements and backpressure; bind declared total bytes and SHA-256, reject missing, repeated, reordered, oversized, or trailing chunks, and reconstruct at most the already bounded full plan. Recompute the plan authority and membership before admission. The TypeScript campaign layer must independently rebuild every request from token-fenced completed source jobs and retained capture leaves, validate source receipts and raw pins, observation membership, per-request descriptor sizes and physical envelope estimates, and recompute the frozen plan. A structurally valid plan or a pure helper result is not source provenance. Do not reserve caller-supplied sizes before that source gate.

The first Python session calls the plan-aware `restartable_registry_startup()` once for the whole batch, with the existing namespace controller attempt limit of 16. It verifies the returned `shardAdmission` against the exact plan authority, publishes the immutable admission receipt, and retains the caller-owned namespace lease. Later sessions validate that terminal receipt under a newly acquired actual lease and do not rerun admission. If the initial admission itself is interrupted, the existing controller may reconcile/retry only the same full plan within its unchanged 16-attempt limit. Preserve original bindings, registry state, and lifetime quota.

After batch-ready, process shards sequentially. For each shard, open its admitted root with the no-SQL child opener, acquire its child writer lease while retaining the namespace lease, and run the existing fixed bootstrap/ingest/audit workers with the planned-shard authority. Release the child lease only after each worker is confirmed reaped; keep the namespace lease through the whole session. A crash or unconfirmed worker keeps the owned process/lease recovery semantics; never infer lease release from a saved PID or a terminal-looking protocol frame.

Expose a separate TypeScript window object with `planHash`, `windowId`, ordered shard identities, `ingestCapture(shardId, input)`, `auditShard(shardId, inputs, attemptLimit)`, and `close()`. Each window numbers its wire calls contiguously from one, with at most 256 capture calls. Audit descriptors and replies have their own existing count, line, per-audit byte, and aggregate output bounds; they do not raise the capture limit. The plan ordinal remains stable across windows and is never reset or renumbered. A window may include a bounded segment of captures and audits, but every listed operation must map to the corresponding deterministic plan and campaign Ledger row. Require the current live token for each row at publication time. Do not allow duplicate or reordered operations, unknown shard IDs, close with an in-flight operation, or a window to claim work outside its declared interval. Individual capture rows and per-shard audit rows retain the original campaign `maxAttempts`; a session/window retry does not grant a fresh attempt budget. The campaign completes only after every shard audit has been verified and the request and observation unions equal the original frozen campaign denominator.

Every window must remain inside the current session limits: 600,000 ms total wall time, 96 MiB Python coordinator RSS, 128,000-byte line frames, at most 256 capture calls, existing audit descriptor/count bounds, fixed-worker CPU/heap/RSS/file/wall caps, and current aggregate stdout/stderr bounds. Multiple per-shard audit replies can exceed the current V1 output allowance if each carries a full report. Return bounded per-shard proof receipts or account for every reply under the existing aggregate bound; do not raise a cap implicitly. Bound plan chunks, retained audit descriptors, and final results before allocation.

## File interfaces and implementation order

1. `feature-index-session.ts`: add separate V3 plan/session config, immutable preparation, chunk framing, client state machine, and typed ready/capture/audit/close receipts. Keep the V1 validator and session state machine unchanged. A pure prepared plan must be tied to privately validated source membership before the campaign persists or dispatches it.
2. `tooling/index_admission.py`: add a separate shard-session entry point and strict frame parser. Reuse signal, deadline, bounded pipe, RSS, error, and owned-process rules from `capture_session()`. Avoid duplicating loose protocol parsers; factor only helpers that preserve V1 bytes and lifecycle behavior. First window admits the complete plan once; later windows validate the immutable receipt and re-acquire the namespace lease without spending a controller attempt.
3. `tooling/index_root.py`: add a no-SQL `precharged_index_shard_root` variant (or better named child opener) taking a private plan authority, the validated batch receipt, held namespace lease, and child hash. Validate the exact receipt, namespace identity, membership, child root/lock identity, and binding. Do not accept a caller-created registry object or open SQLite in the session parent.
4. `tooling/index_bootstrap.py`, `index_ingest.py`, `index_capture_controller.py`, and `index_audit_controller.py`, with their TypeScript fixed-worker supervisors: add explicit planned-child mode carrying expected base/plan/shard pins. Recheck V2 binding and child identity in the fixed worker. Preserve every V1 path and decoder unchanged; V2 is accepted only under the batch authority.
5. `campaign-index-state.ts` and `campaign-index-audit-state.ts`: add a versioned shard-batch binding and one audit-job/completion format for the immutable full plan. Keep existing single-index files and completed capture records readable and unchanged. Store child results/proofs as an ordered exact partition, and qualify only if shard memberships are disjoint and their union equals the same token-fenced Ledger captured set and canonical observation set.
6. Tests: add protocol/state unit fixtures first, then fixed-worker and actual retained-namespace fixtures. Use the real V3 plan admission, real V2 child roots, actual durable capture records, and actual audit workers. Synthetic reports alone must never brand a qualified global completion.

## Recovery and acceptance

The durable V3 controller record is one immutable full-plan operation and retains the original maximum of 16 namespace admission attempts. Once that admission is terminal, every subsequent window reacquires the actual namespace lease, validates (without invoking the admission controller) the exact plan pin, terminal record, successful registry witness, namespace/lock identity, fixed-worker reservation verification, and complete child-root receipt. Only an interrupted initial admission may use the controller's ordinary recovery path, and then only for the same plan/prefix. A different plan, a base-binding change, source receipt/raw mutation, incomplete or extra reservation, unknown child, binding/lock/root replacement, or a plan report mismatch must fail closed before any child capture. Never make a new namespace or change the base V1 binding to reset its charge.

Child capture controllers retain their existing per-capture attempt budget (maximum eight) and durable raw/receipt pins. Child audit controllers retain their own bounded attempts. A confirmed worker failure can settle that operation and permit an exact replay; an unreaped or interrupted worker without terminal cleanup proof preserves its state and ownership. Missing or corrupt child state and exhaustion must refuse completion without deleting the namespace, child database, WAL, or controller records.

Acceptance needs a real nonempty 4,096-unit multi-shard campaign batch that admits all reservations in one V3 attempt, then processes it over multiple capture and audit windows. Verify deterministic 256-operation window cuts, contiguous per-window wire IDs plus stable global plan ordinals, exactly one namespace admission attempt for the completed batch, child lease handoff while each window holds the same namespace lease, no parent SQLite connection, unchanged registry/control charges, and a qualified Ledger completion only after the exact union audit.

Add actual kernel-lock recovery fixtures: after one successful full-plan admission, SIGKILL a real active session coordinator and prove a replacement cannot enter until any surviving worker releases the inherited lock; after confirmed cleanup, reacquire the same namespace/lock inodes, verify the original terminal V3 receipt without increasing its 16-attempt counter, and process the next deterministic window. Replace the namespace directory and, separately, its `writer.lock` inode between windows; both must fail before work and preserve existing state. Also kill at plan transfer, before/after atomic reservation, after child-root publication, during an unconfirmed child ingest, between child releases, and after child audit result but before campaign settlement. Every restart must preserve the quota, reconcile only the exact plan prefix, and either resume safely or remain explicitly incomplete. Include wrong-plan and mutated-source refusal, child-root replacement, missing/corrupt capture record, one exhausted child attempt, one exhausted audit attempt, stale Ledger-token fencing, output/deadline/RSS bound failures, and legacy V1 replay fixtures proving byte-compatible behavior. No fixture may classify process success, a partial shard set, or summed shard-local SQL counts as global audit completion.

## Unresolved boundedness checks

Before implementation is accepted, account the worst-case serialized 4,096-request plan, each 256-capture window, audit descriptor windows and proof receipts against the existing session line, total-output, 2 MiB plan, 512,000-byte per-audit descriptor, and 600-second wall limits. Windowing is mandatory and does not reduce the frozen denominator, re-admit the namespace, or reset any quota. If one deterministic window's protocol data exceeds current caps, reject that window before admission/dispatch or make its operation slice smaller while preserving the full immutable plan and exact global denominator; never silently raise resource ceilings or create additional namespace charges.

The immediate next implementation after the current namespace/controller handoff is a separate reopen verifier plus the first multi-window Python session, in the existing namespace/controller/worker/test ownership lane. Add `index_registry_controller.verify_terminal_shard_admission(...)` as a no-attempt path: under a caller-held namespace lease it checks the canonical V3 record is terminal for the exact plan/base operation, validates the initialized-registry witness and immutable receipt pins, but never calls `restartable_registry_startup()` for an already-admitted plan. Add a fixed `--verify-plan` mode to the existing `index_admission_worker.py` and route it through existing fixed-worker supervision in `index_resource_limits.py`/`index_registry_startup.py`; it checks exact reservations and child roots read-only under current registry worker caps, without `reserve_many` or a controller record mutation. Register the mode in the existing pinned `index_tooling.py` allowlist and existing source-closure accounting; do not add a new fixed module or widen the 1 MiB bucket. Then add the separate shard-session mode in `index_admission.py` using the campaign-owned immutable plan/admission files and sequential child leases. It must acquire and pin the actual namespace/lock identities, execute one declared operation window, and release the namespace lease only after every child worker is confirmed reaped. The first real fixture must admit once, process two windows, SIGKILL between windows, reacquire the same inodes, verify exact same-plan resume with no second V3 attempt, and then add live-worker lock retention plus namespace/lock replacement refusal. Keep campaign/TS window orchestration and global qualification after this Python lifecycle is proven.
