## Wave A ownership and exports

1. Inventory lane owns `inventory.ts`, `inventory.test.ts`, `inventory-cli.ts`, `inventory-sources.json`. Export `buildInventory(source:SourceRecord,geojson:unknown):WorldInventory` and `validateInventory(value:unknown):WorldInventory`; `publishInventory(inventory,outputRoot,allowedRoot)` writes immutable directories/outline data with root manifest last. Natural Earth admin-0 polygons provide geographic foundation only. Preserve source feature IDs, names, continent categories and source-declared country codes; absent/ambiguous codes become explicit exceptions. Territories and boundary disputes reflect the selected source, not sovereign claims. Nigeria is a protected legacy provider entry; no Nigeria content generation. Include source denominator/counts and rollups, climate/terrain/playable unknown. No invented administrative detail. Lazy hierarchy: root -> continent -> country with outlined geometry in independently loaded assets; stable IDs are namespaced by source feature identity. Bounds handle dateline/poles and polygons retain holes. Microstates absent at 110m stay a named source-resolution limitation. Tests must prove no silent missing or duplicate source units and lazy directory counts. Local CLI accepts exact pinned GeoJSON and SourceRecord inputs, safe .cache publication only.

2. Acquisition lane owns `acquire.ts`, `acquire.test.ts`, `acquisition-cli.ts`, `tooling/` (Python adapter, pinned requirements, setup documentation), `acquisition-sources.json`. Export `acquireRegion(request:AcquisitionRequest,options:AcquisitionOptions):Promise<AcquisitionResult>`. Options `{pythonExecutable:string,allowedRoot:string,signal?:AbortSignal}`. Explicit pinned Overture release, region bounds and chosen building/road layers. Adapter outputs sanitised deterministic GeoJSON tagged `building:true`/`highway:<class>`, retains source IDs/heights, layer, source lists in provenance; no contributor/resident identities. Buildings/transportation licences retained. Return WorldPlan-compatible exact input checksum/bytes and bounded acquisition receipt. Reject Nigeria, unpinned releases, unsupported layers/unknown fields, arbitrary executable commands, credentials and unrestricted paths. Parse actual STAC/catalogue or provided pinned file list to avoid scanning every global footer per city. Query bbox overlap plus exact intersection, splitting dateline. One regional extract can feed multiple cells; request identity includes source release/layers/bounds/compiler. Bounded process wall time, rows, output bytes, memory, disk and **network response bytes**. If DuckDB remote network bytes cannot be bounded directly, use a loopback range proxy with byte accounting and allowlisted upstream pinned URLs; don't claim network enforcement merely from output size. Temp output + verify + atomic publish; partial/missing/corrupt source cache revalidated on resume. Setup only official PyPI DuckDB in .cache environment; no paid data calls. Focused tests stub network/process by injected functions where appropriate; actual bounded pilot is acceptance before claiming working production ingestion.

3. Campaign lane owns `campaign.ts`, `campaign.test.ts`, `campaign-cli.ts`, `campaign-fixtures/`, and necessary narrow changes to `pipeline.ts`, `ledger.ts`, `cli.ts` + their tests. Campaign can contain local WorldPlans or AcquisitionRequests, requires explicit inventory/source unit IDs, Africa-first priority, protected Nigeria status, bounded stages/retries and resource caps. Persist campaign ledger separately from M1 ledger. Coordinator supplies acquisition function later; use injection for tests and real acquire.ts export in runner when available. Reuse M1 compile workers/immutable packaging, no repeated root/global catalogue edits. Durable campaign stages acquire -> compile -> validate -> complete/exception. One heavy job at a time; correctly fenced leases; actual deadlines and memory caps for processes; stop/resume and signal handling. Maximum campaign duration configurable up to 48h with per-job caps, not a 48h completion promise. Scope memory/disk/output/network budgets to campaign totals and preserve source cache between runs. Reports separate requested/source/compiled/exception/protected totals, no empty output as success. Codepoint sorting and deterministic config identities. CLI start/run/status/resume usable without model/API calls.
