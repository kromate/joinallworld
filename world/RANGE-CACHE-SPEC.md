# Exact source range cache, version 1

Implement within the existing Python acquisition proxy. This is a builder optimization, with no game imports, new source identities, receipt-schema changes, or budget increases. Existing source receipts and request hashes remain valid. All tests use temporary roots and local fake origins; no real acquisition until review.

## Frozen interfaces and ownership

- `tooling/range_cache.py`: `ExactRangeCache(root: Path, allowed_root: Path, release: str, *, max_bytes=32_000_000, max_entries=256, max_entry_bytes=8_000_000, max_growth_bytes=8_000_000, minimum_free_bytes=32_000_000)`. Canonical release directory is `acquisition-index/<release>/ranges`. `flight(url, file_bytes, first, last)` is a context manager serializing identical reads; bounded/refcounted locks. `get(url, file_bytes, etag, first, last) -> bytes | None`; `put(url, file_bytes, etag, first, last, payload) -> bool`; property `written` is newly published plus retained partial bytes in this invocation. Invalid/symlink cache fails closed; ordinary quota/full-disk skips a write. Store only exact validated 206 spans with strong ETags, exact known total, identity encoding, SHA and byte length. No partial-overlap assembler.
- `RangeProxy(..., concurrency=2, *, range_cache=None)` preserves the existing positional API. Proxy owns fresh HEAD validation and original network accounting, helper owns file integrity/publication/quota. New `range_audit()` returns bounded version1 diagnostics: exact range tuples, hit/miss, body SHA, saved body bytes and measured upstream bytes, counters and explicit truncation. At most64 rows and64KiB canonical bytes. HTTP requests with cache disabled retain prior behavior. Cache-enabled exact hits require a current-process HEAD with status200, strong ETag, identity encoding and full Content-Length equal to pinned STAC length; HEAD headers are charged under the existing budget. Same-process valid HEAD can be reused. Weak/missing validator means no persistent hits/writes; changed validator across processes selects a new identity; change within one proxy fails closed to avoid mixing versions. Per-URL validation must also be serialized, so concurrent identical misses perform one HEAD and one GET when publication succeeds. Conditional subsequent GET uses the verified strong tag. Malformed range responses cannot publish cache entries.
- `run()` enables the helper only in the existing release index. After STAC selection, reserve a bounded growth allowance via `IndexDiskBudget`, subtract the entire allowance from DuckDB temporary disk headroom before queries, then commit actual growth/release unused reservation during cleanup. Allowance is at most8MB and at most one eighth of admitted acquisition disk, further limited by aggregate index remaining disk; skip enabling if no safe space remains. Existing output reserve covers a bounded optional `range-audit.json` in successful acquisition staging, which survives the existing atomic staging rename. No new fields in stdout, GeoJSON, adapter receipt, acquisition receipt or attempt protocol. Failure captures may retain ranges under the shared index; actual shared disk accounting already covers them. Optional diagnostics are not proof of a complete source acquisition.

Root coordinator owns this spec, integration review, checkpoint receipts/docs and actual cache replay. Acquisition worker owns only new `range_cache.py` and integration in `acquire.py` after the prior query checkpoint is committed. Independent worker owns only new `test_range_cache.py` and `test_range_proxy_cache.py`; communicate necessary API corrections before editing shared files. No worker commits or real queries.

## Integrity and bounds

Identity includes release, exact allowlisted URL, pinned file size, exact strong ETag and inclusive first/last. Body/metadata are published together by an atomic directory rename after both fsyncs; incomplete directories never hit. Canonical metadata has exact keys and bounded strings/bytes. Read using no-symlink bounded regular-file APIs; reject symlink ancestors including dangling links. Bound directory enumeration by entries/nodes; orphan temporary bytes count toward aggregate and invocation growth caps. Do not overwrite existing immutable entries or evict STAC, extracts or receipts. A full cache is an optimization miss, never a quota bypass. Reserve temporary publication bytes and free-space headroom before writes, including metadata. Cache reuse reads at most8MB per hit and uses no unbounded in-memory entry index.

Network reservations precede every origin call: HEAD at most8192 response-header bytes; GET requested span plus8192 header bytes. Charge actual headers and body under existing NetworkBudget even when validation rejects. No origin retry silently returns stale bytes. Cache headers to DuckDB are regenerated from verified identity/length/range; do not trust arbitrary persisted HTTP headers. Two concurrent proxy readers retain existing semaphore2 and bounded payload buffers. Internal cache flight/HEAD locks do not replace the existing acquisition process lock.

## Acceptance

Independent local tests cover exact cross-proxy hit (one fresh HEAD, zero repeated GET body), same-proxy/concurrent single-flight, differing ranges/URL/release/tag/size, missing/weak/changed tags, changed file length, invalid/short/oversized Content-Range, non-identity encoding, corrupt metadata/body and symlinks, interruption, full byte/entry/growth/free-space caps, original budget rejection, counted HEAD/miss traffic, no reservation leak and identical served bytes with/without cache. Original8 acquisition cases and3 typed-protocol cases must pass. Final integration must preserve all877 earlier pins, paused schema2 and terminal schema1 replay, and TypeScript; independently inspect telemetry before a bounded real query wave. No country/global throughput or savings forecast from repeated URLs alone.

HTTP semantics reference: [RFC9110](https://www.rfc-editor.org/rfc/rfc9110.html), sections8.8.3,9.3.2,13.1.1 and14.4. Strong tags identify a representation; HEAD Content-Length describes the corresponding GET body; conditional/range validation prevents mixing representations. The stricter cache admission policy above is our bounded implementation choice.
