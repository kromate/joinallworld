# Regional extract reuse and whole-feature ownership

The next additive product derives many child inputs from one pinned local parent extract. It feeds existing local WorldPlan jobs into the existing campaign; it adds no acquisition API, scheduler, game import, Nigeria rewrite or remote call. The first real proof uses cached Dakar, followed by a measured larger regional request and a separately frozen country grid. This is source reuse, not completed-country coverage.

Shared types are frozen in `regional-fanout-types.ts`. Coordinator owns types/spec and integration. Compiler owner edits only `regional-fanout.ts` / its tests. Publisher owner edits only `regional-fanout-publish.ts` / its tests. Independent audit owner edits only `tooling/verify_regional_fanout.py` / its Python tests. No changes to old acquisition/compiler/campaign modules are required.

## Deterministic compiler

Export `validateRegionalFanoutRequest(value: unknown): RegionalFanoutRequest` and `compileRegionalFanout(requestValue: unknown, inputBytes: Uint8Array): RegionalFanoutProduct` from regional-fanout.ts. No I/O, clocks, network or input mutation. Exact input bytes and SHA must match parentPlan.source/input. Canonical JSON plus newline is used for child inputs and index. Request hash is SHA-256 of canonical validated request (sorted child IDs); it includes parent paths and pins. Explicit same-country child denominator, country parent identity, and inventory hash are retained. Nigeria countryCode NG and inventoryUnitId legacy-ng are refused. Parent and child regions must pass ordinary region semantics, valid IANA/null timezone, finite geographic bounds and child containment in the parent, including wrapped extents. Closed child interiors may meet but must not overlap by positive area. Gaps are permitted and reported through outside owners. Child IDs are unique and sorted using code-unit comparison. Child parentId equals inventoryUnitId; do not name-join or infer country relationships.

Hard limits: input 20,000,000 bytes, features 5,000, coordinates 200,000, children 64, aggregate output 30,000,000 bytes. Request limits may lower these and are enforced before large allocation/encoding. Bound request JSON to 256,000 bytes. Reject unsupported schema/unknown request fields, nonfinite or nonsafe limit numbers, oversized and malformed input, duplicate IDs with differing canonical feature bytes, malformed supported geometry, empty multipart geometry, invalid positions and degenerate/unclosed rings. Accept exact duplicate features only as one feature with all source ordinals recorded; source order is not an owner key. Supported buildings follow ingest.ts's building tags and Polygon/MultiPolygon precedence; roads follow highway and LineString/MultiLineString. Preserve all raw feature JSON including properties, holes, multipart order, heights and coordinates, without clipping/snapping. Compiler IDs remain source.id:feature.id/building|road/part. Reject ID reuse across layers/kinds even if layer differs: the existing compiler namespaces at feature ID, not layer. Unsupported feature types/tags have explicit retained hash/ordinal rows and no owner/output parts. Unsupported rows are not success coverage.

For each supported feature, choose the lexicographically least *actual source vertex* after mapping +180 to -180 for ownership only (longitude, then latitude). Coordinate bytes remain unchanged. At shared edges/corners choose the smallest matching closed child ID. This is owner assignment in this frozen local denominator, not authoritative worldwide ownership. A vertex outside every declared child yields outside-denominator with no emitted geometry, never an invented cell. Bounds are whole-feature conservative bounds in the longitude frame nearest the parent midpoint; use them to record all touching child cells, owners and unresolved dependencies, including outside owners. Bounding-box candidates are explicitly not geometry intersections. Large ambiguous extents (>180 longitude span or >25 square degrees) fail closed pending another representation.

Each child gets one exact FeatureCollection with owned whole features only, sorted by stable feature key, and the original metadata plus a regionalFanout provenance object: requestHash, parentInputSha256, logicalCellId, ownership algorithm. Even empty-owned cells get an input/ref/plan. Their touchingFeatureKeys may be nonempty: empty-owned never means empty-query or no physical buildings. Preserve parent source id/url/release/license/attribution; update its bytes/SHA to derived child input. Preserve parent rawExtraction exactly, binding the original parent hash rather than pretending the child was newly downloaded. Plan region ID and metadata match the logical cell, while its compilation bounds expand to contain all whole owned features in the parent longitude frame; wrapped expansion allows existing compiler antimeridian handling. Index retains the original logical child bounds separately. Never hide outside/unsupported rows. Counts reconcile raw rows, unique features, duplicates, owned/outside/unsupported, exact expected part IDs and coordinates. The index records foundation coverage and these limitations.

## Publication and recovery

Export `publishRegionalFanout(requestValue: unknown, options: RegionalFanoutPublishOptions): Promise<RegionalFanoutPublished>`. Read only the pinned parent input and optional pinned acquisition receipt inside allowedRoot. Verify receipt byte/hash and requestHash/input hash/bytes/region plus rawExtraction association; check metadata parent requestHash. It is a source-bound cache artifact, not independent certification of remote capture legality/completeness. Optional null acquisition provenance means an explicitly local parent source. No network imports/fallback.

Validate canonical allowedRoot: exact WORLD `.cache/world-build` for production or an isolated system temporary directory. Reject root/system/repository/game paths, symlink components/targets, input escapes and unsafe output roots. Enforce bounded regular-file reads (including receipt <=1 MB), free disk reserve, aggregate existing dedicated output disk scan, deadline and worker memory limits. Compile in a resource-limited worker terminated on timeout/abort, never synchronous main-thread parsing beyond bounded request/receipt. Maximum duration 60,000 ms; memory 64..512 MiB. Use existing immutable storage: inputs first and content-addressed index last. No separate ledger is added: derivation is deterministic, zero-network and safely resumable through verified immutable collisions; actual compilation uses the durable existing campaign. Cache repeat recompiles from the verified parent and compares all indexed bytes. Published corrupt/missing data fails closed; a published index with a missing child must not silently repair. Incomplete inputs before index publication can resume. Preserve immutable conflicts and interruption evidence. Bounds apply to cache/recovery paths too.

## Acceptance

Compiler tests cover exact conservation with holes/multiparts, closed-edge/corner tie, concave geometry with bbox centre outside, duplicate equality/disagreement, shuffled child/source ordering, outside owners touching a cell, empty-owned touched cells, unsupported tags, finite/geometry/byte/count/request validation, Nigeria/foreign children, overlap/gap, polar and antimeridian ownership and actual downstream compileRegion identity/coordinate parity.

Publisher tests use unique isolated temporary roots. Cover first/repeat identical pins/zero network, parent mutation, receipt mismatch, hostile roots/paths/symlinks, corrupt or missing published children/index, interruption before manifest and safe resume, time/abort/resource limits and pre-publication output caps. No tests write actual builder output or ledger.

Independent Python verifier reads bounded pins/child refs under an explicit root, imports no compiler/pack/publisher, independently rederives source feature identities/vertices/owners/bounds/rows/child memberships/canonical hashes/provenance and conservation from raw parent bytes. Hostile paths, changed coordinates, rehashed bad ownership and missing rows must fail. Compare actual existing campaign output against all expected part IDs/coordinates separately. Real proof must account for all parent features as owned/outside/unsupported and every declared cell, keep original source/acquisition attempts unchanged and run campaign terminal/cache replay with zero new acquisition.

Dependency clarification: cell.ownerDependencies is the distinct, sorted owner CELL ID set for touching features owned by another declared child. It excludes self/null; touchingFeatureKeys already records the feature set and unresolvedFeatureKeys records touched outside/unsupported features. Runtime can use the owner-cell IDs to request complete packs. Unsupported rows with usable bounds also contribute conservative touching/unresolved candidates.

Measured campaign integration refinement: the existing runner rejects zero-tile plans, including local plans. Preserve this behavior. The regional index and publication retain every child input/plan, including empty-owned cells; the campaign adapter verifies every supplied plan but enqueues only owned-features cells plus protected Nigeria. The campaign denominator therefore counts nonempty owner jobs, while the index reports the entire declared cell denominator. The independent emitted-part audit retains every index cell, verifies empty-owned inputs have no expected parts and no campaign job, and verifies all nonempty owner jobs. An all-empty-owned derivation has no geometry compilation jobs; the protected-only campaign result does not certify physical empty geography or completed country coverage.

Publication refinement: after inputs and index, write an immutable completion receipt at `publications/<requestHash>.json` containing schemaVersion 1, requestHash, indexHash, relative indexPath, logicalBytes (index plus child inputs), and inputs (ordered refs). Return its absolute path/bytes/hash as `publication`. This is product completion evidence, not a scheduler or job ledger. Existing receipt requires index and all inputs present/exact; corrupt receipt/index/children must fail closed; missing index/children with a completion receipt also fail closed. An index without a completion receipt can be an interrupted pre-receipt publication and can resume after full verification. Receipt bytes count toward output disk caps separately from logicalBytes. Worker memoryMb is a heap setting; sampled process RSS also has a separate 768 MiB ceiling, including parent/worker in this process. Neither is a physical device performance claim.

Country-wide source-query coverage, a global owner rule across regional extracts, geometry-exact neighbour indexing, runtime cross-pack dependency loading and broad climate/terrain/playability remain later gates. Do not interpret this local derivation's denominator as completed country coverage or attach unsupported source rights.
