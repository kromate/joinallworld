# Africa urban-detail scaling review

## Recommendation

Do not treat the Dakar/Addis Ababa/Dar es Salaam sample cells as the next coverage endpoint. Use them only to prove that source-selected anchors, country links, Overture selection, stable feature IDs, and downstream pack compilation work at three more points. Then implement a **bounded regional extract-and-fan-out path**, and exercise it against a frozen country-area cell denominator before adding more independent city jobs. The first testable national sweep can use Senegal because Dakar already supplies one exact place reference; it must cover the entire declared eligible grid, including explicitly empty cells, rather than only the Dakar cell. This is a source-query-coverage experiment, not an assertion that Senegal's urban settlements/buildings are complete.

The current acquisition request and campaign job each bind exactly one region. The Python adapter already constructs a release-wide STAC item index and caches it at `.cache/world-build/acquisition-index/<release>`, but the **parquet range reads are not cached/reused across distinct region requests**. Each request separately selects overlapping STAC items, creates a fresh `RangeProxy`, queries remote parquet through DuckDB, and saves one request-hash-specific GeoJSON under `.cache/world-build/acquisitions/<requestHash>/extract.geojson`. A cached STAC index therefore saves metadata work; it does not prevent repeated reads of the same regional parquet bytes when many nearby cells are requested. See `tooling/acquire.py::select_item_index`, `RangeProxy`, and `read_layer`; `acquire.ts::acquireRegionUnlocked` creates a distinct request hash, staging directory, receipt and per-request cache.

## Evidence and limits

The accepted representative campaign planned 7 source units plus protected Nigeria. It ended with 4 compiled source units (Accra, Nairobi, Cape Town, London), two explicit empty-geography exceptions (Sahara and Antarctica), one Fiji transport failure after two attempts, and Nigeria protected. The compiled packs contain 1,123 features / 439,741 input bytes. Campaign-wide network accounting is 113,303,391 bytes: 49,303,391 measured plus 64,000,000 retained reservation for the failed Fiji transfers whose actual size is unknown. The measured 49,303,391 includes 45,539,637 bytes for the successful uncached Cape Town/London/Nairobi acquisitions and 3,763,754 bytes for an empty-source acquisition; Accra had an earlier separate uncached v2 acquisition of 16,519,093 bytes for 314 features / 113,357 GeoJSON bytes in 44.826 seconds. Receipts and summary are in `M2-VALIDATION.md`, `campaign-fixtures/README.md`, `.cache/world-build/evidence/representative-v2-final-resume-3.report.json`, and `.cache/world-build/evidence/accra-overture-acquisition-v2.json`.

These few cells show why a linear national forecast is not credible: downloaded Range bytes differ greatly from output bytes and feature counts, and empty/failing cells still consume time/accounting. Do not extrapolate a per-city or per-feature transfer multiplier into an Africa/global budget. Failures with unknown transfer remain charged at their full reservation; the failed Fiji attempts are a concrete example. Empty output is recorded as an exception, not proof of complete coverage.

The existing acquisition limits are hard ceilings, not scale targets: adapter maxima are 32,000,000 response bytes, 20,000,000 GeoJSON bytes, 50,000 features, 900,000 ms, 2,048 MiB, and 256,000,000 disk bytes per request. The representative fixture is more conservative per job (32,000,000 network, 10,000,000 output, 5,000 features, 600,000 ms, 1,536 MiB, 128,000,000 disk). Its campaign cap is 256,000,000 network, 80,000,000 unique input bytes, 100,000,000 compiled-output bytes, 1,500,000,000 disk bytes, 5,400,000 ms total, 600,000 ms per job and two lifetime attempts per unit. Preserve these caps for the initial batch path. Split dense shards deterministically when any per-job cap is reached; do not raise caps or silently drop features. Campaign quotas and attempt history remain cumulative across resume.

## Concrete next code milestone

Add an additive regional batch acquisition path that leaves the existing `acquireRegion` implementation, cache-key identity and `WorldPlan` contract intact. The new path accepts a frozen parent extent plus a sorted, explicit list of child cell regions and acquires them through one shared regional extraction. Reuse the pinned release configuration and `select_item_index`/`RangeProxy`; select candidate parquet assets once for the union of child regions, execute one bounded per-layer spatial read over that union, and write a content-addressed regional extract/index. From that verified cached extract, derive exact per-cell GeoJSON inputs locally for existing `compileCampaignPlan` jobs. A cache repeat must verify the regional manifest, source pin and every indexed feature/input hash before returning zero network; it must never replace a corrupt immutable collision or erase a pending/failed attempt. Avoid wrapping old requests in a new identity unless their existing cached request hashes still resolve unchanged.

Initial code ownership should stay narrow and use the existing ingestion surface:

- `world/tooling/acquire.py`: bounded multi-region selection/query over the already-pinned STAC index and shared range proxy. Keep bbox-overlap pruning followed by exact geometry intersection. Read each selected parquet asset once per batch/query where possible; meter every upstream response byte and retain unknown reservations on interruption.
- `world/acquire.ts` plus new focused `world/regional-acquire.ts` and tests: versioned request/receipt/cache identity for the parent extent and sorted child region IDs/bounds; publish one immutable shared extract/index; fan out verified child inputs using the existing `AcquisitionResult`/`WorldPlan` interfaces. Keep `acquireRegion` API, source IDs and prior cache keys unchanged; an eventual one-child adapter must be additive and preserve existing identity.
- `world/campaign.ts` integration only after the batch module is reviewed: enqueue the full child-cell denominator with stable per-cell unit IDs and use the existing durable campaign ledger, stage journal, budget settlement, `--max-jobs`, `status`, and `resume`. Avoid a parallel scheduler/ledger.
- Keep `world/ingest.ts` and compiler IDs stable. The regional index must retain original provider feature IDs/layer/source metadata and exact geometry; no centroid-only filtering, coordinate snapping or name-based reassignment.

A useful offline acceptance fixture is one small synthetic regional extract shared by several overlapping child cells. Assert one regional query/read per selected source asset, duplicate-source-ID detection, exact geometry/ID conservation, cache-only repeat with identical hashes and zero network, child-input parity against the existing one-region path for the fixture, and explicit empty/failed/over-budget/not-started cell states. This demonstrates reuse without running or claiming a real national acquisition.

## Coverage denominator and ownership gates

Before any country sweep, freeze a deterministic grid origin/step and derive a sorted eligible-cell list by intersection with the accepted pinned parent outline. The accepted Natural Earth map-unit outline is a reproducible geography input, not an official/legal jurisdiction boundary. A country-wide grid is a query denominator, not a city/town inventory or built-up-area mask; empty rural cells do not demonstrate complete settlement capture. Freeze the entire expected cell-ID set and parent source/manifest hashes before acquisition; do not grow the denominator opportunistically after seeing source results. Each ID should be derived from the country map-unit ID and integer grid indices (not city name or mutable list order). Preserve country IDs and `legacy-ng` protection; never infer place-to-cell assignments by names.

Define feature ownership before turning the regional extract into playable or overlapping packs. Stable source identity is currently `overture-<release>-<layers>` and compiler feature IDs prefix the Overture feature ID with that source identity (`ingest.ts::featureItems`). A geometry intersecting several child cells may appear in several independently acquired extracts today. The regional extract should deduplicate by `(source layer, stable Overture feature ID)` and report disagreements if duplicate copies differ. Then establish a deterministic, tested boundary rule for buildings and roads: either a single canonical owner with geometry retained once, or explicit geometry partitioning that preserves source lineage and child-segment IDs. The current compiler preserves source coordinates and may expand tile bounds to fit a whole feature; it is not a cross-cell ownership/deduplication service. Do not claim unique country totals until the rule is implemented and independently verified.

The full cell accounting must distinguish at least `not-started`, `pending`, `complete-with-features`, `complete-empty`, `failed-known-bytes`, `failed-unknown-bytes`, and `deferred-over-budget`. Empty means the bounded source query returned no supported feature for that cell, not that the place has no buildings/roads. Failed or deferred cells cannot count as completed coverage. A campaign may finish operationally with exceptions; product-level coverage remains incomplete unless every frozen eligible cell reaches a documented terminal result and all stored outputs are verified.

## Unknowns to resolve with measured evidence

The current receipts do not reveal national Overture parquet bytes, urban feature density by fixed cell size, number of STAC assets touched per country, cost of a union query, or how much overlapping cell queries repeat row groups. The representative receipts are not a statistically useful forecast. The initial batch implementation should report per-asset bytes, selected item counts, query bounds, per-cell features/bytes, wall time, peak memory, and shared-cache hits; preserve actual transfer separately from unknown reservations. Run one explicitly authorized bounded regional batch, inspect its verified report, then select the next batch size from those measurements. Do not redownload/retry the old Fiji request or alter its retained reservation.

Overture source attribution and ODbL-1.0 configuration remain as pinned in `world/acquisition-sources.json`; source attribution is not a resolution of all source-specific rights or public distribution conditions. Detailed coverage also does not supply measured terrain, routing, playability or game/save migration permission. Nigeria remains outside this system.

## Coordinator decision after the accepted sample batch

Dakar/Addis Ababa/Dar es Salaam now conserve 2,972 captured features in 1,162,375 pack bytes, using 37,290,835 measured upstream bytes. See AFRICA-URBAN-SAMPLES-OPERATIONS.md. The immediate implementation should derive a frozen child-cell set from one hash-verified cached regional extract, publish a full source-bound ownership/conservation index, and compile local child plans through the existing campaign runner. Start with the accepted Dakar extract, then measure one larger bounded parent extent through existing acquireRegion. Do not modify the Python query path merely to support an extent already expressible by its existing request.

Before implementation, the coordinator must freeze the additive fan-out types and ownership rules. Retain complete source features once, use an actual source vertex for deterministic ownership rather than a bbox centre that can lie outside the geometry, and index full intersecting extents for neighbouring views. Features owned outside the child denominator must remain explicit; empty owned cells do not mean no source geometry touches the cell. Country-grid coverage and authoritative global ownership require their own frozen denominator and verification. A partial regional fan-out cannot claim complete-country coverage.
