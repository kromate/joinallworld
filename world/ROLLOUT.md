## Nigeria and database independence

Treat the existing Nigeria implementation as a protected provider. Keep its IDs, map frame, saves, catalogue, travel rules and database implementation as they are while the independent builder runs. A separate worktree protects simultaneous edits; a separate output directory and SQLite file protect build state. A future adapter resolves `legacy Nigeria` or `world pack` before loading a map. It must not wrap existing saves in a new global schema as a side effect. The current server owner retains ownership of server/database changes.

The eventual integration changes only the map/content reader boundary, adds a lazy hierarchical destination directory, and introduces explicit country/timezone metadata for new destinations. Map compilation never writes player records. Source refreshes cannot rename a player's home ID or delete ownership. Missing/replaced features require aliases/tombstones and an explicit migration review. Overture IDs have stability commitments that vary by type, and split/merge mappings are not guaranteed; store an internal game ID plus release-qualified source references. [GERS stability](https://docs.overturemaps.org/gers/stability/), [registry](https://docs.overturemaps.org/gers/registry/).

The current all-pairs travel generator remains limited to legacy Nigeria. New providers use road/ferry connected components, region-border connectors and a sparse hub graph. No flight edge merely because two airports exist. Use an indexed shortest-path backend or precomputed corridor graph later; never include the world's routing graph in the browser bootstrap. Gameplay server partitioning is a separate milestone with capacity measurements and cross-region transaction rules, not something a CDN resolves.

## Geographic production pipeline

The separate 258-unit directory and its lazy preview are accepted. Administrative metadata has been rejoined against that full denominator; explicit new-parent binding and a durable cache-only campaign have passed real first/repeat Rwanda runs. This is the reviewed-input execution milestone. Next add bounded source capture/promotion and topology preparation for more African countries, then partition over-limit administrative layers without changing old products. See [FINE-CAMPAIGN.md](FINE-CAMPAIGN.md) for admission rules and exact next tasks.

1. Freeze a release inventory: Natural Earth overview, gbOpen administrative release, Overture Buildings release, OSM/Overture transportation choice, terrain and climate releases. Include country/territory source coverage and disputed-boundary source policy. Administrative units have types rather than assuming state/city/LGA everywhere.
2. Resolve source URLs once, checksum downloads, record source timestamp and extraction tool version. Freeze the inventory for the run. A moving `latest` URL is discovery only. Use bounded regional queries or one regional extract followed by spatial indexing. Do not repeat a whole national PBF scan per city.
3. Build coarse global geographic coverage first. Source absence is an exception with a count, not an empty successful country. Then deepen Africa by country, then other continents. Country completion is relative to a frozen list and coverage level; inhabited cities, uninhabited cells and Antarctic stations have different requirements.
4. Generate tile-local metre geometry. Keep complete source features in one owner cell initially; index each feature's full intersecting extent so a neighbouring view can request its owner. This avoids duplicate identities and false walls from naïve polygon clipping. Later buffered clipping must have one canonical boundary quantisation and source-part keys, with seam tests. Large features and sparse areas need a coarser representation, not endless subdivision.
5. Validate source references, geometry topology, IDs, heights, bounds, budgets, attribution and coverage exceptions. Package immutable tiles with hashes. The manifest is the last published artifact. Hash checks precede decoding, and the reader pins a manifest for a session so updates do not mix geometry versions.
6. Generate an exception report, country rollups and representative render screenshots. Promotion to a playable destination requires the separately tested gameplay contract. No amount of geometry declares businesses open or invents usable interiors.

Overture's documented bounded DuckDB path is the initial bulk acquisition choice. Use bbox *overlap* then geometry intersection, split dateline queries, retain stable feature IDs and source lists. Export one reusable indexed regional dataset, then cut many packs locally. Install and pin GIS tools in the builder environment only after the measured pilot chooses them; no DuckDB/Arrow in the game bundle. [Overture data access](https://docs.overturemaps.org/getting-data/duckdb/).

The small Accra pilot is a captured source snapshot, not the production download strategy. Public OSM editing APIs and raster tile servers must not become unattended world downloaders. Use official bulk extracts or an appropriate data host. [API policy](https://operations.osmfoundation.org/policies/api/), [tile policy](https://operations.osmfoundation.org/policies/tiles/).

## Climate, terrain and photorealism

Use ERA5 for region-scale climate normals, selecting a documented baseline such as 1991–2020. Store grid resolution, temporal period, variables, units and processing version. Temperature, relative humidity, precipitation totals and wind speed have different aggregation rules. In particular, do not claim that relative humidity computed from monthly mean temperature/dewpoint equals mean hourly relative humidity, or that the magnitude of mean wind components equals mean wind speed. Compute derived variables before aggregation or clearly label the approximation. Start with pilot regions before scheduling a global multi-decade extraction. [ERA5 monthly product and variable definitions](https://cds.climate.copernicus.eu/datasets/reanalysis-era5-single-levels-monthly-means?tab=overview).

Climate means are not today's weather. Default to a labelled climate baseline; future simulated variation must be deterministic, spatially coherent and bounded by source distributions. Optional current weather stores provider product type, effective time, collection time, TTL and fallback mode. Monthly precipitation in millimetres must not be reused as instantaneous rain intensity. A collector operates on selected game cells, not each player's GPS. Paid commercial weather access is a separate configured service; the first pipeline is offline-capable and makes no weather purchase.

Photorealism has three independent gates: source rights, measured rendering cost, and fidelity. Real footprints with estimated heights are useful now. Exact facades/interiors need licensed reference data; AI-generated plausible textures remain labelled representations. Preserve a low-detail mesh on every device. Terrain ingestion must distinguish DSM from bare earth and convert vertical datums before mixing elevations with WGS84 ellipsoid frames. Antarctic holes in terrain coverage get explicit flat/unknown fallback. Snow/cold is sourced per region/season; Africa has wet tropical, dry desert, savanna, Mediterranean and highland conditions.

## Device and operating budgets

The first measured production device target should be a named low-end Android available to the team; emulation is not a physical-device FPS measurement. Before widening rollout, record CPU/GPU/frame time, peak resident memory, decoded geometry size, bytes to first scene and camera movement under latency/packet loss. Existing Nigeria startup limits remain fixed. New preview limits are tuning gates, not evidence that mobile performance already passes.

Start with two content requests, 60 KB Brotli per tile, 90,000 total visible triangles, 40 total visible calls and approximately 50 MB automatic cache. Count all visible geometry and draw calls, including ground/props and overlays. Brotli estimates are not actual transferred bytes unless the server negotiates compression. Cache eviction/disposal and cancelled requests need soak tests. Disk cache failures must not prevent play from the network. User-selected offline downloads show measured total bytes and remain separate from authoritative gameplay writes.

For unattended local operation, run one GIS/compile worker at first. Bound each source download, job input, output, maximum attempts and run duration. Enforce free-disk reserve before large downloads; a CPU wall-time limit needs a worker process that can be terminated, not just a clock check between synchronous jobs. Cancel gracefully, stop claiming, finish/abandon the lease and leave resumable immutable outputs. Do not silently retry permanent validation errors forever. SQLite WAL is local disk; a multi-host fleet requires a different queue/storage coordination design.

An initial two-day run can have a two-day time budget; that does not guarantee whole-world detail. Measure source bytes/s, features/s, tiles/s, p95 job duration, failure rate and resulting download sizes on Accra, Nairobi, Cape Town, London, Antarctic and sparse/dateline samples. Use those measured rates and source-unit counts to forecast the continent batch. Never extrapolate a tiny city fixture into a global time guarantee.
