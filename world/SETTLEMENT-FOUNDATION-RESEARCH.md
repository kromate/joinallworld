# Settlement point inventory: admission research

Historical candidate review below is preserved. Subsequent bounded capture and independent schema admission are accepted in [SETTLEMENT-OPERATIONS.md](SETTLEMENT-OPERATIONS.md) and `settlement-admission.json`: 7,342 valid points, 7,257 direct linked / 68 protected Nigeria / 17 unmatched; literal uppercase NE_ID and ADM0_A3 verified. Exact bytes/blob/SHA and missing-parent/code exceptions are now known. The historical unknowns below are not current status. Compact publication and lazy reading remain next.

## Scope and evidence

The next proposed geography layer is a compact global **city and town reference-point inventory**. It should support map labels and geographic orientation only. A point is not a building footprint, an address, a navigable destination, or a playable location. This is a candidate source review, not a claim that global settlements are complete.

Natural Earth's [10m Populated Places description](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-populated-places/) describes named point symbols and says the layer includes all admin-0 capitals, many admin-1 capitals, major cities and towns, plus a sample of smaller towns in sparsely inhabited regions. It explicitly favors regional significance over a population census and recommends scale ranks to filter labels. Those statements rule out interpreting this product as an exhaustive settlement inventory or using its population values as a complete census. The page identifies website release 5.1.2; that is not proof that a Git file at another pinned revision is byte-identical to that website release.

The repository file is visible at [the exact pinned GitHub path](https://github.com/nvkelso/natural-earth-vector/blob/ca96624a56bd078437bca8184e78163e5039ad19/geojson/ne_10m_populated_places.geojson), at commit `ca96624a56bd078437bca8184e78163e5039ad19`. GitHub's rendered metadata reports **18.5 MB (rounded)**. This browser review did not expose the Git blob SHA or exact byte count, and no geometry or raw-file download was made. Record neither as an exact pin yet: the next admission task must verify the raw source SHA-256, exact byte length, and Git blob identity from the already authorized bounded source capture or Git metadata. Keep commit, capture time, and Natural Earth website release as distinct provenance fields; the commit alone does not establish the page's version label or a source observation date.

The Natural Earth repository's [maintainer issue on populated-place properties](https://github.com/nvkelso/natural-earth-vector/issues/494) describes `NE_ID` as the record identifier and lists fields including `NAME`, `NAMEASCII`, `FEATURECLA`, `ADM0_A3`, `ADM0NAME`, `ISO_A2`, and `ADM1NAME`. It says `ADM0_A3` and `ISO_A2` are based on the Natural Earth country containing the place, and describes `ADM1NAME` as based on Natural Earth admin-1 or a real-world value. This is useful schema evidence from the source repository, but it is a 2021 issue scoped to new records during a v5.0.0 workflow—not a schema guarantee for every feature at the pinned commit. It does not establish an exact row key, null behavior, uniqueness, ISO semantics for every disputed/overseas map unit, or a reliable ADM1 foreign key. Therefore:

- Treat `NE_ID` as a **candidate stable feature key**, not an accepted key, until the exact pinned capture proves type, canonical form, presence, and uniqueness for every retained row.
- Treat `ADM0_A3` and `ISO_A2` as **candidate country-join fields**. Do not silently choose between them or coerce special values. The admission audit must compare actual per-value coverage to the already accepted country/map-unit directory and explicitly account for unmatched, ambiguous, and protected rows.
- `ADM1NAME` is descriptive text, not a parent identifier. Do not assign admin-1 parents by matching names. A later parent link needs a source-backed code/key plus a documented country-specific crosswalk; otherwise leave it unlinked.
- Verify `NAME`, `NAMEASCII`, `FEATURECLA`, population/rank fields, coordinate shape, and their missing/value distributions against the pinned bytes before defining public fields. Preserve source distinctions; do not infer population totals or locality status from a label alone.

## Proposed product boundary

Use the accepted Natural Earth full-source commit as a candidate parent for the 10m populated-place GeoJSON, then publish a deterministic, compact directory of point records with separately lazy country indexes. Keep raw geometry out of the browser bundle and fetch only the selected country index/point part. The public contract should bind every output to the full source pin and to the exact accepted country-directory manifest hash. Sort by canonical source key (with source ordinal retained for audit), preserve the source WGS84 point coordinate exactly, and use content-addressed immutable assets. Do not generate synthetic places, snap points to roads/coastlines, add unreviewed third-party rows, or claim administrative containment without a proven join.

Recommended initial limits for review (not yet an implementation contract): source at most 32 MiB; no more than 100,000 accepted source rows; a 16 MiB logical published aggregate; each country index/part at most 512 KiB; and at most 100,000 published point positions per country. The pinned page's rounded 18.5 MB suggests the source-size ceiling may be sufficient, but exact bytes and worst-case serialization have not been verified. Keep actual browser response caps at or below the existing country-directory route limits; do not widen a route limit to make this product fit. If measured records or indexes exceed the budget, fail preflight and design a reviewed representation rather than dropping places or truncating silently. A point-only representation should have a much smaller geometry budget than polygon products, but the output cap still needs measured evidence.

At runtime, load the small hash-pinned manifest first and one country index/part on demand. Bound concurrent fetches, response bytes, cache bytes, feature counts, and parsed numeric coordinates; abort and await obsolete reads before releasing their budget. A failed or stale hash must clear the current selection and visible labels. Keep labels visually distinct from building meshes and provide a simple-map/list fallback. Population and scale rank may inform optional label filtering only after their exact semantics and null distributions are audited; neither should suppress records from the underlying inventory.

## Nigeria accounting

The existing geography spine reports 258 country/map units and 4,596 source units, with four real building pilots. Those are separate denominators and do not describe populated places. The number of Nigeria place records in the pinned source, the number assigned to the protected Nigeria map unit, and the number excluded from a generic city layer are **unknown** from this metadata-only review. Do not reuse the Nigeria polygon count, building count, or any country-directory count as a settlement count. During admission, report raw source rows, rows with valid point coordinates, rows assigned to Nigeria under the verified country join, protected rows, and global retained rows as separate counts. The existing user instruction already fixes the policy: retain `legacy-ng`, exclude Nigeria from new builder geometry and reference-point publication, and make that protection visible. Calculate the exact excluded count from the pinned source; do not manufacture substitute points. Nigeria's separately implemented rendering improvements do not change this source-admission policy.

## Admission tasks

1. **Pin and schema audit (metadata/cached input only).** Verify the exact file's commit path, Git blob SHA, byte count, SHA-256, UTF-8/GeoJSON structure, top-level schema, and all property keys without altering the source. Produce full row counts, null/value distributions, duplicate/missing `NE_ID` counts, point-coordinate validity, and exact country-field value coverage. Record capture time separately from source commit and the website's 5.1.2 description. Do not begin a network fetch as part of this review.
2. **Country joins and Nigeria protection.** Crosswalk candidate country codes to the accepted directory by code, not names. Publish explicit match/unmatched/ambiguous counts; review special codes and map units. Apply the existing `legacy-ng` exclusion and calculate its protected count from the verified source only. Do not create an ADM1 relation from `ADM1NAME` text.
3. **Budgeted deterministic prototype.** On fixtures first, specify schemas and exact output ceilings, stable IDs, sorted country indexes, cache/abort rules, immutable publication, and failure behavior. Then run a supervised, bounded build only after pin, field, country-join, attribution, and Nigeria-exclusion reviews are accepted. Compare first and repeated builds for identical hashes and enforce the existing route caps.
4. **Product validation.** Test antimeridian and polar points, duplicate city names, missing labels, special country codes, empty country indexes, Nigeria exclusion, stale requests, corrupted part hashes, and cache conservation. Present the output as selected places, never as every settlement or evidence of buildings/playability. Capture representative global/Africa counts and disclose any country-level gaps.

## Unresolved evidence and coverage gap

This source is intentionally selective: it omits some admin-1 capitals and samples smaller towns in sparsely populated regions. It cannot by itself satisfy an “all settlements” requirement. A later Africa-focused enrichment would need a separately admitted source with an explicit compatible license, dated/versioned pin, stable place IDs, and a country-code crosswalk; verify its identity, coverage, duplicate policy and attribution before combining inventories. The present source review did not inspect raw records, verify the exact feature-key field or country-code coverage, or establish a Nigeria count. Those remain admission evidence to collect, not assumptions.
