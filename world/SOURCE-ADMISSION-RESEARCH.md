# Fine-source admission research: BFA, CIV, GMB, and AGO

This is a source and license review, not a grant of rights or a policy change. It concerns local acquisition of the exact geoBoundaries `gbOpen` ADM1 source, with publication/distribution remaining a separate decision. The frozen promotion implementation currently admits only Natural Earth records meeting its Public Domain and Natural Earth terms checks; it binds the selected metadata row, catalogue, directory, and full geoBoundaries commit in a request. The geoBoundaries package license and the upstream boundary source license are distinct facts.

## Provider evidence and its limits

**World Bank records (BFA, CIV).** The official [Burkina Faso catalog record](https://datacatalog.worldbank.org/search/dataset/0039809/burkina-faso-administrative-boundaries) states the dataset shows 13 regions and 45 districts, says the data were curated from HDX/OCHA, links to the external HDX record, lists 2018 resources, and labels the catalog dataset CC BY 4.0. The official [Côte d’Ivoire catalog record](https://datacatalog.worldbank.org/search/dataset/0040515/cote-divoire-administrative-boundaries) likewise says it was curated from HDX/OCHA, links to HDX, lists 2018 resources, and labels the catalog record CC BY 4.0. These support the frozen CC BY metadata label and provenance trail, but the catalog pages describe regional/district resources last updated in 2018; they do not, by themselves, prove that the exact geoBoundaries ADM1 artifacts used for the 2017/2016 rows are byte-identical to those resources or that the original upstream rights cover every transformation.

### Exact BFA/CIV upstream follow-up

The frozen metadata `boundarySourceURL` values were checked verbatim. BFA ordinal 14 points at `datacatalog.worldbank.org/dataset/burkina-faso-administrative-boundaries-2017`; CIV ordinal 33 points at `datacatalog.worldbank.org/dataset/cote-divoire-administrative-boundaries-2016`. Those legacy URLs currently return 404, but their World Bank catalog IDs resolve to records `0039809` and `0040515` above. The World Bank EnergyData pages are the catalog's current resource views and expose exact resource identifiers and resource-level license/date/description:

* BFA's [World Bank Group Burkina Faso 2017 catalog page](https://energydata.info/en/dataset/burkina-faso-administrative-boundaries-2017) lists the 13-region GeoJSON resource. Its resource ID is `36d34b89-c2c4-4d14-9418-640c70f47627`, and the linked official World Bank file path is `datacatalogfiles.worldbank.org/ddh-published-v2/0039809/1/DR0049488/bfaadmbndaadm11msalbitos.geojson`. The [resource page](https://energydata.info/dataset/burkina-faso-administrative-boundaries-2017/resource/36d34b89-c2c4-4d14-9418-640c70f47627) labels it GeoJSON, “13 regions boundary polygon,” CC BY 4.0, last updated Nov. 14, 2018. This matches the frozen row's represented year (2017), 13-unit count, and ADM1-region semantics. The resource filename carries `msalbitos`; the visible catalog metadata does not explain that token or identify the original geometry producer more precisely than its HDX link.
* CIV's [World Bank Group Côte d’Ivoire 2016 catalog page](https://energydata.info/dataset/cote-divoire-administrative-boundaries-2016) lists a 14-district GeoJSON resource, ID `4568121e-bc5a-419d-818d-882286ca631f`, with official World Bank path `datacatalogfiles.worldbank.org/ddh-published/0040515/1/DR0050529/civadmbndaadm1cntig20160527.geojson`. The [resource page](https://energydata.info/dataset/cote-divoire-administrative-boundaries-2016/resource/4568121e-bc5a-419d-818d-882286ca631f) labels it “District Boundary,” 14 polygons, CC BY 4.0, last updated Nov. 14, 2018. The file name encodes `adm1`, `cntig`, and `20160527`; the metadata's source update date is Aug. 30, 2023 and its represented year is 2016. This is a strong product-level metadata match for the frozen 14-unit ADM1 row, though the original source organization, the significance of the 2023 source update date, and source-to-geometry derivation are not explained on the resource page.

Both World Bank pages currently identify the origin platform as HDX and the contact as the OCHA regional/country office; both label the dataset/resource CC BY 4.0. The OCHA Centre's primary [HDX license guidance](https://centre.humdata.org/ufaqs/data-licenses/) lists available licenses (including CC BY-IGO, PDDL, and CC0) and says other license terms may be supplied in the dataset description, metadata, or included license file. Its primary [data-sharing guidance](https://centre.humdata.org/ufaqs/sharing-data/) states that contributors choose an appropriate license and may share third-party data only if the applicable license allows onward sharing. This confirms that HDX's platform status is not itself a blanket license, and also means the exact contributor-selected terms matter.

The HDX landing pages linked from both catalog records returned HTTP 403 through the available page reader, and the official HDX package API could not be retrieved through the browser reader. Thus the current review has not verified the HDX package's exact contributor, dataset-level `license_id`, resource IDs, original metadata, or any `license_detail`/attribution file. The World Bank resource pages themselves offer relevant independent evidence: they explicitly label the exact 13-region and 14-district resources CC BY 4.0. Because the World Bank also describes these as curated third-party HDX datasets and tells users of external third-party data to consult the external license, the missing exact HDX contributor/license record remains a real chain-of-rights question rather than a reason to promote the row automatically.

**Source-to-pinned-row proof remains incomplete for both.** Resource unit count, layer type, vintage, and candidate path prefix agree with the frozen rows, and the catalog rows explicitly link these World Bank records to their sources. But no geometry bytes were retrieved, so no direct hash/equality/feature-level comparison was made between `DR0049488` or `DR0050529` and the candidate geoBoundaries objects at full commit `9469f09592ced973a3448cf66b6100b741b64c0d`. Metadata concordance is evidence of intended lineage, not proof that the exact bytes or every derivation step match. The matching resource records are also unchanged since 2018, while [OCHA says COD-AB datasets should be reviewed every 12 months](https://knowledge.base.unocha.org/wiki/spaces/imtoolbox/pages/2557378679/Administrative%2BBoundaries%2BCOD-AB); treat these as historical snapshots rather than current administrative coverage. The material reviewed does not establish the current review status of either exact package.

**Narrow next step for BFA/CIV:** obtain the HDX package metadata records for slugs `burkina-faso-administrative-boundaries` and `cote-d-ivoire-administrative-boundaries` from HDX's `package_show` API or contributor through an accessible primary channel. Capture only bounded metadata, not geometry. Bind the package `id`, `name`, `organization`, `metadata_modified`, selected `license_id`, `license_other`, and each resource's `id`, `name`, `url`, `last_modified`, and resource metadata to the catalog records above. Confirm that the license permits this local copy, processing, and immutable source-cache retention and that no source terms conflict. If available, compare a provider-supplied checksum for the exact 2018 resource to geoBoundaries' pinned-file checksum; do not infer byte identity from the counts or filenames. If the upstream record is unavailable, preserve the present status as unresolved and request confirmation from the listed OCHA contact before adding either row to an allowlist.

The [World Bank's licensing guidance](https://datacatalog.worldbank.org/public-licenses) says CC BY is its default for datasets produced by the Bank, while also saying many datasets use other licenses; where the Bank supplies metadata for third-party data available externally, users should consult and follow the external site's license. It also notes ODbL distribution where the original provider or partnership requires it. Since these two catalog records identify HDX/OCHA as the curation path, the useful additional evidence is the exact linked HDX resource's license, attribution, and provenance/version metadata and its connection to the published geoBoundaries geometry. The World Bank record's CC BY label is significant evidence, but should not be treated as proof of rights beyond the scope its own guidance describes.

**Gambia (GMB).** The frozen row points its `boundarySourceURL` to the [World Bank blog article](https://blogs.worldbank.org/en/opendata/hidden-potential-mobile-phone-data-insights-covid-19-gambia). That article describes an anonymized mobile-phone-data analysis and mentions work with the Gambia Bureau of Statistics and PURA; it is not a boundary dataset page and does not state a boundary-data license. The row's separate `licenseSource` points to catalog ID `0038034`, but that record was not available at the supplied URL during this review. The article's discussion of districts and its reuse of World Bank CC BY wording do not establish rights in the polygon source. This row has a material provenance/license gap and should remain ineligible until an exact boundary dataset record and its terms (including upstream rights) are located and bound to the row. The geoBoundaries project itself distinguishes gbOpen's CC BY 4.0 package license from its humanitarian feed, which may have less-open upstream licensing.

**Angola (AGO).** The Census [subnational population and mapping page](https://www.census.gov/geographies/mapping-files/time-series/demo/international-programs/subnationalpopulation.html) describes Census estimates linked to administrative maps. Its current Angola entry is for communes (ADM3), and the linked current product is an Angola boundary package. That is not a direct confirmation of the frozen 2021/18-province ADM1 layer. The official Census [geographic metadata guide](https://www2.census.gov/programs-surveys/international-programs/about/global-mapping/geo-metadata-pgs-uscb-dec16.pdf) says its international shapefiles may draw on national agencies, GADM, UN sources, and other sources; warns that restrictions from some origins apply; and directs users to each shapefile's metadata for citations and restrictions. It also explains that Census fits boundaries to U.S. State Department LSIB/WVS international boundaries, may use older administrative vintages, and cannot guarantee positional accuracy. Therefore the frozen `Public Domain` value plus the fact that Census is a U.S. agency is not adequate source-specific evidence for this foreign boundary artifact. The exact Angola package's included metadata, upstream source(s), restrictions, and relationship to the 2021/18-unit row must be inspected before even local ingestion is admitted. Current Census listings show a different administrative level, so staleness and layer identity require particular care.

**geoBoundaries package terms.** The [geoBoundaries API/source documentation](https://www.geoboundaries.org/api.html) says `gbOpen` is CC BY 4.0 compliant and expects attribution; it separately warns that `gbHumanitarian` can be less open and describes the fields that record a boundary's primary source, original license, license evidence, and source dates. The [geoBoundaries repository license](https://github.com/wmgeolab/geoBoundaries/blob/main/LICENSE) covers project code and derivative works under CC BY 4.0. This supports recording the package-level geoBoundaries attribution/license for an admitted `gbOpen` artifact; it does not substitute for the upstream source's own license or establish that a specific input geometry was authorized for inclusion. Keep `originalLicense` as the upstream claim, and record the package license separately.

## Proposed extra local-ingestion predicate

Do not widen the existing predicate to “any row whose `boundaryLicense` string says CC BY/Public Domain.” Add a versioned policy only for rows meeting **all** of these evidence-bound conditions:

1. The exact raw metadata row, full metadata snapshot, catalogue report, country-directory manifest, and full immutable geoBoundaries commit are hash-pinned and mutually consistent, as the promotion flow already requires; row ordinal, `boundaryID`, ISO3, candidate path, represented year, unit count, source, original license, and evidence URLs must match the catalogue.
2. The geoBoundaries package is exactly `gbOpen` from a full commit and exact country/ADM1 path, and the package attribution/license is preserved separately from the upstream source rights.
3. The original provider's page or embedded per-file metadata is primary evidence that identifies the exact boundary product or source version and grants local copying/processing for this use. It must state terms that permit this copy. `Public`, a general institutional statement, a broad source portal, or a license string without an exact artifact/provenance join is insufficient.
4. Every identified upstream contributor/source has compatible terms or a documented applicable exception; no “for humanitarian use only,” non-commercial restriction, unlicensed component, or conflicting downstream license is silently overridden by geoBoundaries' package label.
5. The version/vintage and administrative level are explicit and consistent with the selected ADM1 layer; count agreement is only a sanity check, not a substitute for source identity. Preserve provider spelling/IDs/provenance; do not infer a legal boundary status or rewrite coarse country IDs.
6. The policy scope is local, bounded acquisition and immutable internal source storage only. It does not authorize public redistribution, paid use, gameplay claims, legal boundary representation, or a claim that the source is current. Those require their own review and attribution presentation.

**Row-specific outcome today:** BFA and CIV have a plausible path to further review because their official World Bank catalog records state CC BY 4.0 and link the HDX/OCHA source, but the exact underlying 2017/2016 artifact and upstream license chain still need confirmation. GMB is not admissible because the cited blog is not the boundary data source and the row's dataset record is unavailable. AGO is not admissible yet because the exact Census package metadata and upstream restrictions are missing, and the current Census page points to a different level/vintage. This review does not find that any of the four is already cleared by the proposed predicate.

## Smallest next review/implementation

First, collect only provider metadata (not polygon geometry) for BFA/CIV's exact linked HDX resources, the missing GMB dataset record/source, and the exact Census Angola package metadata corresponding to the 2021/18-unit row. Record the primary provider URL, version/date, origin contributors, explicit license/restrictions, and a hash of each small metadata document. Ask the data provider only if those records leave a material rights ambiguity. Then implement a separate, versioned local-ingestion profile with allowlisted evidence-source shapes and explicit upstream/package-license fields; test it with synthetic metadata and negative cases for missing evidence, stale/different level, incompatible restrictions, and unrelated license strings. Do not download the four boundary geometries until that evidence gate is met.

The source rows are old snapshots (2023 catalog build; represented years 2016–2021). Re-evaluate later provider updates as new pinned evidence rather than mutating stable IDs or refreshing geometry in place. Stable fine IDs remain bound to source feature keys and explicit migration records; a revised source may require reviewed migrations and cannot silently change identity.
