# Terrain source contract and bounded Accra pilot

This is a source contract and isolated source-sidecar pilot, not a gameplay change. The one Accra COG is allowlisted by exact URL and object length. The metadata probe below records no pixel observations; the measured sidecar, once produced by the bounded CLI, is the separate record for any inspected raster samples. Its source checksum is computed from the complete COG and is never inferred from ETag.

## Source semantics and evidence

Copernicus GLO-90 is a **digital surface model (DSM)**. It may represent roofs, infrastructure and vegetation, so it is not bare-earth terrain and cannot supply building-ground elevations without further processing. The product handbook specifies WGS84-G1150 / EPSG:4326 horizontally, EGM2008 / EPSG:3855 vertically, metres, and a nominal 3 arc-second GLO-90 grid. The handbook documents variable longitude sampling by latitude; the exact bands are listed in [`terrain-sources.json`](./terrain-sources.json). The source-product datum is documented, but the probed AWS COG has no vertical GeoKey. A future sidecar must preserve that distinction: identify the product datum while recording that the tile header does not independently prove it. Do not label samples as ellipsoidal heights. Conversion to the game's WGS84 ellipsoid frame requires a pinned, compatible EGM2008 geoid model and validated geodesy; no converter is specified here.

The product is delivered as one-degree geocells. The Accra pilot cell is `Copernicus_DSM_COG_30_N05_00_W001_00_DEM`, covering the geocell from 1°W to 0° and 5°N to 6°N. The exact COG URL, object length (3,511,272 bytes), HTTP metadata, and parsed TIFF header observations are recorded in the source registry. The header reports 1200×1200, one 32-bit band, EPSG:4326, PixelIsPoint, and a 3 arc-second scale. The initial metadata probe read only 16,384 bytes and no samples. The subsequent bounded full download supplied the SHA-256 and measured sample evidence below. S3 ETag is never treated as a content hash.

The AWS registry describes global GLO-90 COG availability, with no tiles over ocean; absence means missing coverage, not a measured height of zero. The product handbook's `-32767` no-data code applies to EEA-10, not GLO-90. GLO-90 no-data/fill/ocean sample encoding therefore remains unverified at this metadata-only stage. Do not silently map absent tiles, invalid samples, water masks, or unknown fill values to zero. Preserve any available editing/filling/water masks in a future ingestion and count exceptions. Polar longitude spacing changes by latitude, and the Copernicus documentation carries regional quality caveats; validate the latitude band and report source limits rather than assuming a globally uniform square grid.

Copernicus describes GLO-90 as derived from WorldDEM and provides attribution language for use of modified products. Every future published manifest must carry the current required notice: “Produced using Copernicus WorldDEM-90 © DLR e.V. 2010-2014 and © Airbus Defence and Space GmbH 2014-2018 provided under COPERNICUS by the European Union and ESA; all rights reserved.” Check the current official terms before redistribution; this contract does not grant additional rights.

## Bounded source-to-sidecar contract

`terrain-cli.ts` processes **only the known Accra geocell**, with no bucket listing or global crawl. The worker uses the exact COG object and a 5,000,000-byte aggregate response-body cap (the observed object is 3,511,272 bytes). It counts bytes across failed attempts and retries, allows at most two attempts and 60 seconds, rejects an unexpected Content-Length before reading, and aborts streaming when the cap is crossed. The Node supervisor enforces the 60-second wall bound and samples the Python worker's RSS against a 384 MiB cap. (An address-space cap is not used because the macOS runtime begins with virtual mappings larger than that RSS budget.) The pilot store enforces a 30,000,000-byte disk cap including attempt records, staging, quarantine/partial evidence, source and sidecar. These are local limits, not provider guarantees.

Before decoding, validate the regular file, pinned length and computed SHA-256. Cache under the source-content hash; never trust ETag as content hash. Rasterio/GDAL validates the 1° geocell, CRS, PixelIsPoint, dimensions and pixel spacing, then reads only the small native pixel window intersecting the Accra Overture request bounds `[-0.207, 5.552, -0.203, 5.556]`. The sample grid preserves valid zero elevations. No-data recognition uses the dataset's nodata metadata and GDAL mask; the code does not borrow another Copernicus product's sentinel. The sidecar contains sample values and coordinates, mask counts, native raster metadata, and source hash. No resampling or geoid conversion occurs.

Publish immutable raw source and sidecar files by writing bounded temporary files, syncing, then creating exclusive hard links at content-addressed paths, without overwriting existing destinations. Publish the immutable cache index last. The CLI holds the shared acquisition lock until the worker has exited. A partial or invalid download remains as a bounded, auditable attempt artifact; valid cached sources and manifests are immutable and are never removed on resource-limit errors. Attempt records are append-only/fsynced, capped at 1 MiB and 16 KiB per record. A campaign runner must separately enforce its broader shared-cache budget; this terrain pilot does not claim a global disk cap.

The sidecar records the source URL/tile identity, exact source length and SHA-256, horizontal CRS, DSM semantics, source-stated vertical datum plus whether it was present in the tile header, native grid spacing, exact sampled window and method, mask/nodata state, derivation version, attribution, and explicit exceptions. For PixelIsPoint, GDAL still exposes a pixel-corner affine: use `ds.xy(row, col, offset="center")` for the native sample coordinate, half a pixel from that corner. See [GDAL RFC33](https://gdal.org/en/stable/development/rfc/rfc33_gtiff_pixelispoint.html). The vertical reference is product-handbook-stated while the COG vertical GeoKey is absent. Until a tested geoid conversion exists, mark `ellipsoidConversion: "not-applied"` and do not attach these elevations to the current game world pack, whose contract expects WGS84 ellipsoid heights.

Admission is cumulative for this pilot: before fresh network access a durable 5 MB reservation is written. Success replaces it with measured body bytes; failed/interrupted runs retain the reservation and block further fresh acquisition. A validated cache hit is allowed without network even with retained reservations. Cache hits verify source and sidecar hashes, lengths, request/derivation pins and exact reproduction from source pixels. The pre-fetch free-disk reserve is 100 MB.

The contract types are in [`terrain-types.ts`](./terrain-types.ts); source evidence is in [`terrain-sources.json`](./terrain-sources.json). The CLI is `node --experimental-strip-types world/terrain-cli.ts`; set `WORLD_PYTHON` to the private terrain-venv's Python 3.12 executable if needed. Output and attempt evidence live under `.cache/world-build/terrain/`.

The isolated builder environment uses pinned official PyPI artifacts in [`tooling/requirements-terrain.txt`](./tooling/requirements-terrain.txt). Setup is separate from the bounded tile job. Resolve each exact compatible wheel URL from official PyPI JSON, download into `.cache/world-build/tooling/terrain-wheelhouse`, count every response body byte (including retries) against a 100 MB setup response cap, hash each wheel before install, and persist URL/version/filename/bytes/SHA-256 plus aggregate bytes in `terrain-setup.json`. Measure expanded setup disk separately, cap it at 500 MB, and preserve 100 MB free disk. Install offline with `--no-index --no-deps --require-hashes`; do not add packages to root/game dependencies.
