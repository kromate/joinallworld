# Bounded Overture acquisition tool

The builder-only acquisition adapter runs from a private Python 3.12 environment under `.cache/world-build/tooling/venv`. It does not add GIS or DuckDB packages to the game or root npm dependencies. Use `world/acquisition-cli.ts` with an explicit request file and the environment's absolute Python path.

Setup is intentionally separate from acquisition because installing Python packages or DuckDB extensions requires network access outside a regional job's byte budget. Install only the pinned requirements from the official Python Package Index, then install the official DuckDB `httpfs` and `spatial` extensions once into `.cache/world-build/tooling/extensions`. The adapter loads those cached extensions from that fixed directory and refuses to install them during a region job.

```sh
python3.12 -m venv .cache/world-build/tooling/venv
.cache/world-build/tooling/venv/bin/python -m pip install --disable-pip-version-check --no-input -r world/tooling/requirements.txt
.cache/world-build/tooling/venv/bin/python -c 'import duckdb,pathlib; c=duckdb.connect(); d=str(pathlib.Path(".cache/world-build/tooling/extensions").resolve()); c.execute("SET extension_directory=" + chr(39) + d + chr(39)); c.execute("INSTALL httpfs"); c.execute("INSTALL spatial")'
```

The adapter uses a pinned Overture release and the corresponding static STAC item catalogues in `world/acquisition-sources.json`. It builds and verifies a shared release item index once under `.cache/world-build/acquisition-index/`; each item document has its own atomic cache receipt so an interrupted index build resumes without refetching completed items. It then selects only STAC items whose own bbox overlaps the region. Regional jobs enforce a Node-supervised process RSS limit and wall deadline, Python CPU/file limits, DuckDB memory/temp-disk limits, and row/output limits. STAC requests and GeoParquet HTTP range reads share the response-byte budget. GeoParquet reads pass through a loopback proxy that only serves pinned allowlisted asset URLs, allows at most two concurrent requests, and reserves each requested range plus response-header allowance before contacting upstream. The request's bounds are split at the antimeridian; selected STAC items are bbox-filtered, and rows receive explicit `bbox.xmin/xmax/ymin/ymax` overlap predicates for row-group pruning plus exact geometry intersection.

The resulting GeoJSON and acquisition receipt live under `.cache/world-build/acquisitions/<request-hash>/`. The extract is deterministic for a pinned request; the receipt records the exact input hash and byte count, upstream URLs/ETags/bytes, selected layer source licences and source dataset lists, and exceptions. Resume verifies the receipt and extract before returning a `WorldPlan`. A valid cache that exceeds the current output or feature limit is retained and the request fails with a budget error; it is not treated as corrupt or downloaded again. A corrupt or partial exact-request cache is renamed into a `.quarantine-<request-hash>-...` directory, kept as audit evidence, and may be repaired at most three times for that hash.

Each request also writes append-only attempt evidence to `.cache/world-build/acquisition-attempts/<request-hash>/attempts.jsonl`. A start record is fsynced before cache inspection or adapter launch, so an interrupted attempt remains visible on resume. Finish records contain success metrics and the receipt path, or a failure reason with `networkBytesMeasured: null` and the reserved network upper bound. The evidence log is capped at 1 MB and 100 attempts per request hash. This local metadata cap is enforced independently of the requested job disk budget; campaign-level disk usage is accounted for by the campaign runner.

Direct `acquireRegion` calls serialize on `.cache/world-build/.acquisition-build.lock`. Campaigns use `withAcquisitionBuildLock` around shared-cache budget measurement and acquisition, and call the supplied unlocked acquirer from inside the callback. This keeps the budget check, cache growth, and usage journal under one shared-root lock. Lock files use an exclusive create, fsync, owner identity, stale dead-process recovery, and a bounded wait.

Acquisition compiler identity `world-source-compiler-v2` includes only Overture transportation segments whose `subtype` is `road` in the `roads` output layer. Regional rail and water omission counts are explicitly unknown because this bounded query does not make an additional scan to count them. Existing `world-source-compiler-v1` cache entries are retained unchanged; those extracts predate the subtype filter and may include rail or water features tagged as roads. Overture's Buildings and Transportation attribution is retained in the source records; see <https://docs.overturemaps.org/attribution/>.

## Copernicus GLO-90 Accra terrain pilot

The source-sidecar pilot is separate from the game bundle and uses Rasterio/GDAL only in a private builder venv. Create `.cache/world-build/tooling/terrain-venv` from the repository's existing private Python 3.12.14 interpreter. `world/tooling/requirements-terrain.txt` pins every runtime dependency and its official PyPI wheel SHA-256. Resolve only compatible wheel files from the official PyPI JSON API, stage them in `.cache/world-build/tooling/terrain-wheelhouse`, and verify every downloaded body against its pinned SHA before installation. Setup response bodies (including retries and PyPI metadata) are capped at 100 MB total; record URL, wheel filename, version, exact response bytes and hash in `.cache/world-build/tooling/terrain-setup.json`. Measure expanded setup disk separately, cap it at 500 MB, and preserve 100 MB free disk. Install from the wheelhouse offline with `pip install --no-index --no-deps --require-hashes -r world/tooling/requirements-terrain.txt`; do not modify root dependencies.

Run one tile only with `WORLD_PYTHON="$PWD/.cache/world-build/tooling/terrain-venv/bin/python3.12" node --experimental-strip-types world/terrain-cli.ts`. The exact tile URL is hardcoded and allowlisted in `world/tooling/terrain.py`; no user URL or listing is accepted. The adapter caps combined source response bodies at 5 MB cumulatively for this request hash across runs, with up to two transport tries inside an admitted run; successful runs count measured bytes, while failed or interrupted admitted runs retain their full 5 MB reservation. A validated cache hit remains available without network admission. Runtime is capped at 60 seconds, worker RSS at 384 MiB, pilot cache/audit/staging disk at 30 MB, and individual source or metadata files at 5 MB / 1 MB. Attempt logs are append-only and fsynced before network use. Failed partial bytes remain as bounded audit evidence. The COG and sidecar publish immutably by actual SHA-256. The sidecar samples only native GLO-90 pixels inside the Accra Overture request bounds, uses Rasterio nodata and the GDAL mask, records PixelIsPoint sample coordinates using center coordinates and verifies the RFC33 half-pixel affine shift, and records product-stated EGM2008 semantics without ellipsoid conversion. Complete-object bytes/hash, mask results and sidecar path are recorded separately from the earlier header-only probe in `world/terrain-sources.json`.

## Independent fine-product verification

`verify_fine_pilot.py` uses only Python's standard library, reads bounded local files and never imports the compiler, writes output or contacts the network. It independently checks the complete pin/parent binding, original source geometry (including holes), source keys and names, stable IDs, bounds, every referenced asset hash/byte count, source-bound planar report, registry and coverage metrics. It supports direct active identities; migrations are explicitly rejected rather than inferred. Parent hierarchy/identity assets are verified, but parent outline geometry is outside this verifier's scope.

```sh
python3 world/tooling/verify_fine_pilot.py --repository-root "$PWD" --manifest .cache/world-build/output/fine/ly/adm1/manifests/3c8994beebc35240e405b38b7ffc8e90671eb22f03ae2493ce49b1117465d613.json --pin world/fine-source-lby.json
python3 -m unittest discover -s world/tooling -p 'test_verify_fine_pilot.py'
```

Success emits a JSON verification receipt to stdout; rejection emits JSON with exit code 2. Six isolated fixture tests cover source/asset corruption, count mismatch, safe paths/symlinks and complete geometry including holes. Actual Rwanda, Djibouti and Libya products passed read-only verification; evidence is retained under `.cache/world-build/evidence/`.

## Selected-place raw/schema audit

`audit_settlement_source.py` independently reads saved `world/settlement-sources.json`, `settlement-parent.json` and `settlement-capture.json` pins. It checks exact source bytes/SHA/Git blob, parent manifest/identity binding, duplicate JSON keys/nonfinite values, literal fields, key uniqueness, Point coordinates and country joins. It emits one bounded JSON report without network or filesystem writes. Run with the private Python and a shared heavy slot; preserve original hash-bound evidence and save replays under new filenames. See [SETTLEMENT-OPERATIONS.md](../SETTLEMENT-OPERATIONS.md). This is source admission evidence, not a published point product or complete-world claim.

## Independent selected-place product reconstruction

`verify_settlement_product.ts <manifest-sha256>` imports only Node built-ins and reconstructs the admitted source/parent joins and every published point/label/ordinal/feature hash. It rechecks the admitted capture metadata and raw-audit evidence, canonical cache identities, complete parent node/identity chain, all country rollups and actual bounded asset references. It uses no network and writes only its stdout receipt. Run through a heavy slot, retaining a new replay filename. See [SETTLEMENT-PUBLICATION-OPERATIONS.md](../SETTLEMENT-PUBLICATION-OPERATIONS.md) for commands, measured results, limits and the explicit scope boundary. This check does not independently inspect parent outline geometry or duplicate raw JSON keys, establish official containment or validate playability.
